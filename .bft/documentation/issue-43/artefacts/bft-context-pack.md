# 2. Факты из po-statement.md

**Источник:** Issue po-helper-org/poh-demo-checkout#43 (заменяет эпик трекера)

**Запрос:**
- Сейчас оформить заказ можно только после регистрации: на шаге оплаты форма требует логин, часть покупателей уходит
- Хотим разрешить оформление без учётной записи: почта + адрес доставки → письмо со статусом + ссылка на регистрацию позже
- Существующий флоу с регистрацией остаётся, гостевой добавляется рядом
- Почта обязательна — по ней ищется заказ в поддержке
- Повторный заказ на ту же почту не должен создавать дубль профиля

**Уточнения заказчика (последние, приоритет над ранними):**
1. Почта уже привязана к зарегистрированному аккаунту: заказ оформляется как гостевой, письмо содержит приглашение войти (не регистрацию), после входа заказ привязывается. Никаких подсказок о существовании аккаунта на форме — утечка факта регистрации.
2. Обязательны: почта, адрес доставки, телефон для курьера. ФИО опционально.

**Контекст прогона:**
- Прогон на сборке с entire: диалог стадий пишется чекпоинтами в ветку, при обрыве сделанное публикуется с id сессии
- Текст дословно повторяет #41 (эталон, прогон `claude -p`), этот идёт с `BFT_DIRECT_STAGES=draft`

**Артефакты смежного прогона (#41):**
- Упомянут как референс для сравнения

# 3. LLM-синтез

## 3.1. Домен и контекст

**Что делает эпик:** Внедряет гостевой заказ — возможность оформить покупку без обязательной регистрации, с последующей возможностью привязки заказа к профилю. Покупатель вводит контактные данные (почта, адрес, телефон), получает письмо со статусом, а позже может завести аккаунт или войти — тогда прошлые заказы подтянутся.

**Домен:** E-commerce, оформление заказа, аутентификация/регистрация, управление профилями пользователей. (glossary.md: гостевой заказ, SKU)

**Затрагиваемые сервисы и БД:**
- Frontend — форма гостевого оформления (ввод почты/адреса/телефона/ФИО)
- Order Service — API контракт `/quote` с полем `guest`, валидация данных
- User Service — профили пользователей, логика слияния гостевого заказа в профиль
- Email service — отправка письма со статусом и ссылкой (архитектура.md: не задокументирован, но требуется задачей)

## 3.2. As-Is (текущая ситуация)

**Как работает сейчас:** (architecture.md + po-statement.md)
- POST /quote принимает `{items: [{sku, quantity, price}]}` и считает сумму, доставку, итог
- Оформление заказа требует обязательной регистрации/входа на шаге оплаты
- Арифметика в pricing.mjs, HTTP-обёртка в server.mjs
- Зависимостей нет, стандартная библиотека Node.js

**Источник истины:**
- Код: src/pricing.mjs, src/server.mjs
- Контур: README.md, CLAUDE.md
- Постановка: po-statement.md

**Что считается болью/проблемой:** (po-statement.md)
- Часть покупателей уходит на шаге оплаты из-за обязательной регистрации
- Цель — снизить отток, разрешив гостевой заказ

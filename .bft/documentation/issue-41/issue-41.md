# [БФТ] issue-41: Гостевой заказ без регистрации

## Бизнес описание

Образ результата: Покупатель может оформить заказ без создания учётной записи, введя email, адрес доставки и телефон. Гостевой заказ сохраняется в системе с флагом `is_guest`, покупатель получает письмо с подтверждением и ссылкой для входа или регистрации. Существующий флоу с обязательной регистрацией остаётся доступным параллельно.

Зачем делать: Снизить отток покупателей на шаге оплаты, где часть уходит при требовании обязательной регистрации. Метрика: доля успешно оформленных заказов от начатых оформлений.

<details><summary>Подробный контекст</summary>

Текущая система требует обязательной регистрации на этапе оплаты. Часть покупателей покидает оформление на этом шаге, не завершая заказ. Введение гостевого флоу позволит этим покупателям оформить заказ без создания учётной записи, снижая барьер конверсии.

Гостевой заказ хранится с флагом `is_guest` в той же таблице заказов. Письмо отправляется через stdlib (`nodemailer`) в рамках принципа «без внешних зависимостей» (D-002). Привязка гостевых заказов к профилю при регистрации вынесена в SubIssue после MVP.

</details>

### Сценарий приёмки

```plantuml
@startuml
actor Покупатель
actor "Оператор Поддержки" as Support
participant "Форма оформления" as Form
participant "Система заказов" as Orders
participant "Рассылка" as Email

== Гостевой заказ ==
Покупатор -> Form: Выбирает «Оформить без регистрации»
Form -> Form: Вводит email, адрес, телефон
Покупатель -> Form: Подтверждает заказ
Form -> Orders: Создаёт гостевой заказ (is_guest=true)
Orders -> Orders: Сохраняет email, phone, address
Orders -> Email: Отправляет письмо с подтверждением
Email -> Покупатель: Письмо со статусом + ссылка

== Email уже привязан ==
alt Email не привязан к аккаунту
    Email -> Покупатель: Ссылка на регистрацию
    Покупатель -> Form: Регистрируется
    Form -> Orders: Привязывает гостевой заказ к профилю
else Email уже привязан к аккаунту
    Email -> Покупатель: Приглашение войти
    Покупатель -> Form: Выполняет вход
    Form -> Orders: Привязывает гостевой заказ к профилю
end

== Поддержка ==
Support -> Orders: Ищет заказ по email
Orders -> Support: Возвращает гостевой заказ

== Повторный заказ ==
Покупатель -> Form: Оформляет ещё раз с тем же email
Form -> Orders: Создаёт новый гостевой заказ
Orders -> Orders: При регистрации привязывает все заказы

== Существующий флоу ==
Покупатель -> Form: Выбирает «Зарегистрироваться»
Form -> Form: Стандартный флоу регистрации
@enduml
```

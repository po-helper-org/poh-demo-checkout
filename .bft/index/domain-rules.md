# Domain Rules — Бизнес-правила

## Правила расчёта заказа

### DR-1: Стоимость доставки
Базовая стоимость доставки составляет 300 рублей. [источник: src/pricing.mjs:5]

### DR-2: Бесплатная доставка
Доставка бесплатна при сумме заказа от 3000 рублей включительно. «От 3000» означает включительно — расхождение стоило бы дороже, чем читается. [источник: src/pricing.mjs:9-10]

### DR-3: Минимальная сумма заказа
Минимальная сумма заказа для оформления составляет 1000 рублей. [источник: src/pricing.mjs:12-13]

### DR-4: Валидация цены позиции
Цена позиции должна быть конечным числом (Number.isFinite) и неотрицательной. Иначе выбрасывается ошибка «некорректная цена в позиции {sku}». [источник: src/pricing.mjs:28-31]

### DR-5: Валидация количества
Количество позиции должно быть целым числом (Number.isInteger) и больше нуля. Иначе выбрасывается ошибка «некорректное количество в позиции {sku}». [источник: src/pricing.mjs:32-34]

### DR-6: Обязательные позиции
Заказ не может быть без позиций — выбрасывается ошибка «заказ без позиций». [источник: src/pricing.mjs:25-27]

## Git-workflow правила

### GW-1: Issue первым делом
Любая доработка ведётся через Issue. Без Issue работа не начинается — цель прозрачной хронологии. [источник: CLAUDE.md:6-8]

### GW-2: Ветка = Issue
Формат ветки: `feature/<номер>-<slug>` либо `fix/<номер>-<slug>`. [источник: CLAUDE.md:11]

### GW-3: PR = Issue
PR должен содержать `Closes #<номер>` в теле для связи с исходным Issue. [источник: CLAUDE.md:12]

### GW-4: HowToDemo в Issue
Конкретный сценарий проверки готовности — что запустить, что сделать, что должно получиться. Нет HowToDemo — нет критерия «готово». [источник: CLAUDE.md:9-10]

### GW-5: Хронология непрерывна
Значимый шаг — комментарий в Issue, а не только в логе прогона. [источник: CLAUDE.md:13]

### GW-6: MVP первым, edge-кейсы — в SubIssue
Найденный по дороге edge-кейс не берётся в работу сразу — выносится в SubIssue с `root-issue: #N` и меткой `origin:agent`. [источник: CLAUDE.md:15-18]

# Stakeholders — Стейкхолдеры

## Роли в контуре производства

| Роль | Описание | Зоны ответственности |
|---|---|---|
| **PO (Product Owner)** | Заказчик, выставляет требования через Issue. | Запрос на доработку, утверждение HowToDemo, решение на точках передачи |
| **Issue-Agent** | Триаж и классификация Issue. | Метки advisor:*, priority:*, phase:*, дедуп, приоритизация |
| **FNR (System Analyst)** | Аналитика через цепочку навыков. | БФТ → системные требования → декомпозиция на MVP/GROW/SUPPORT |
| **OpenHands (Developer)** | Разработка на раннере GitHub Actions. | Код, тесты, PR с Closes #N, запись edge-кейсов в .followups.md |
| **PR-Agent (Reviewer)** | Ревью PR. | Проверка кода, комментарий с verdict, круги правок |

## Внешние стейкхолдеры

| Роль | Описание | Взаимодействие |
|---|---|---|
| **GitHub** | Платформа для Issue, PR, Actions. | Хостинг репозитория, webhook для workflows |
| **Temporal** | Оркестрация workflow контура. | `IssueLifecycle`, `IssueAnalysis`, дочерние прогоны |
| **JIRA/Confluence** | [UNAVAILABLE] Трекер и wiki в корпоративном контуре. | В этом демо-контуре не подключены |

## Команды

| Команда | Ответственность | Артефакты |
|---|---|---|
| **Frontend** | Фронтенд-реализация гостевого заказа | UI форма ввода почты/адреса/телефона |
| **Backend (Order Service)** | Логика обработки заказа, валидация | API контракт `/quote` с полем `guest` |
| **Backend (User Service)** | Профили пользователей, привязка заказов | Логика слияния гостевого заказа в профиль |

| Точка | Что решается | Кто решает |
|---|---|---|

# Architecture — Архитектура системы

## Системный контур

**Тип:** Демо-стенд контура производства Issue → Аналитика → Разработка → PR → Ревью
**Назначение:** Проверка автоматизации полного цикла, а не предметной области
**Репозиторий:** po-helper-org/poh-demo-checkout [источник: README.md:3-6]

## Компоненты системы

### Сервис расчёта заказа

**Назначение:** Маленький HTTP-сервис для расчёта стоимости заказа
**API:** `POST /quote` — считает сумму позиций, доставку и итог [источник: README.md:27-35]

**Структура кода:**
- `src/pricing.mjs` — вся арифметика, чистые функции без ввода-вывода [источник: AGENTS.md:16-17]
- `src/server.mjs` — тонкая HTTP-обёртка: разбор запроса и коды ответов [источник: AGENTS.md:17]
- `tests/pricing.test.mjs` — тесты расчёта (node:test) [источник: AGENTS.md:18]

**Константы бизнеса:**
- `DELIVERY_FEE = 300` — стоимость доставки [источник: src/pricing.mjs:5]
- `FREE_DELIVERY_FROM = 3000` — порог бесплатной доставки (включительно) [источник: src/pricing.mjs:9-10]
- `MIN_ORDER_AMOUNT = 1000` — минимальная сумма заказа [источник: src/pricing.mjs:12-13]

### Контур производства

**Workflow полного цикла:**
```
Issue заведён
  └─ Issue-Agent: триаж (advisor:* + priority:* + phase:classified)
       └─ аналитика FNR → ветка research/issue-N + системные требования
            ├─ остались вопросы [УТОЧНИТЬ] → комментарий и ожидание ответа
            └─ декомпозиция → SubIssue по релизам MVP / GROW / SUPPORT
                 └─ ready-for-dev + чеклист готовности
                      └─ OpenHands: разработка → PR с Closes #N
                           ├─ edge-кейсы по дороге → .followups.md → SubIssue
                           └─ PR-Agent: ревью
                                └─ круг правок → /review → «замечаний нет»
```
[источник: README.md:8-19]

**Две активности контура:**

| | Research | Develop |
|---|---|---|
| Работает с | Issue, текстом, аналитиком | веткой, кодом, PR |
| Цель | превратить запрос в описанный документ: БФТ → системные требования → декомпозиция | взять Issue и автономно разработать, протестировать, открыть PR, довести по ревью |
| Кто исполняет | цепочка FNR через `claude -p` в воркере | OpenHands headless на раннере GitHub Actions |
| Видно в | Temporal: `IssueAnalysis` | Actions: `OpenHands Resolver` |

[источник: DEMO.md:27-34]

### Автоматика контура

| Workflow | Когда | Что делает |
|---|---|---|
| `ci.yml` | PR и push в main | тесты |
| `openhands-resolver.yml` | диспатч от Issue-Agent (либо метка `fix-me`) | разработка по Issue → PR |
| `pr-review.yml` | три входа: вызов из разработки, событие `pull_request`, команда `/review` в PR | ревью PR-Agent + доклад в цикл |

[источник: README.md:48-52]

## Workflow точка передачи

`ready-for-dev` — единственное место, где контур сам отдаёт работу человеку. `DEVELOP_AUTOSTART=1` эту паузу снимает. [источник: DEMO.md:35-37]

## Границы архитектуры

- **Код пишет OpenHands, а не контур** — живёт на раннере GitHub Actions [источник: DEMO.md:102]
- **Ревью не чек-лист «исправлено/нет»** — `/review` заново ревьюит текущий диф [источник: DEMO.md:105-106]
- **Merge остаётся за человеком** — контур доводит до состояния «готово к слиянию» [источник: DEMO.md:107-108]
- **Зависимостей у сервиса нет** — это свойство, а не упущение [источник: README.md:37-38]

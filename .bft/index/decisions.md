# Decisions — Архитектурные решения

## AD-1: Разделение арифметики и HTTP
**Решение:** Вся арифметика в `pricing.mjs` чистыми функциями, HTTP-обёртка в `server.mjs`.
**Обоснование:** Расчёт проверяется тестом построчно, и подмешивать сеть значило бы проверять вместе с ней. [источник: src/pricing.mjs:1-3]

## AD-2: Стандартная библиотека вместо зависимостей
**Решение:** Зависимостей у сервиса нет — используется только стандартная библиотека Node.js.
**Обоснование:** Это свойство сервиса, а не упущение. Новая зависимость заводится, только если задачу нечем закрыть из стандартной библиотеки. [источник: README.md:37-38; AGENTS.md:21-23]

## AD-3: HTTP 400 для бизнес-ошибок
**Решение:** Ошибки валидации и бизнес-логики возвращаются как HTTP 400, а не 500.
**Обоснование:** Битый JSON — ошибка запроса, а не сервера: 500 здесь увело бы разбор в логи сервиса вместо ответа клиенту. [источник: src/server.mjs:34-36]

## AD-4: Подзадачи декомпозиции своей разработки НЕ заводятся
**Решение:** Весь объём MVP исполняет родитель одним прогоном и одним PR.
**Обоснование:** Иначе на репозитории одновременно работали бы несколько агентов. [источник: README.md:21-23]

## AD-5: Edge-кейсы уходят в SubIssue, не чинятся в той же ветке
**Решение:** Найденный по дороге edge-кейс записывается в `.followups.md` и выносится в SubIssue с `root-issue: #N` и меткой `origin:agent`.
**Обоснование:** Граница MVP — HowToDemo. Пока HowToDemo не проходит, делается только то, что к нему ведёт. [источник: CLAUDE.md:15-18; AGENTS.md:36-42]

# Концепты решений для FNR-1: Мультивалютный расчёт цены

**На основе:** `task.md` от 2026-08-19  
**Анализ кода:** `repomix-output.xml` + `src/pricing.mjs`, `src/server.mjs`, `tests/pricing.test.mjs`

---

## 1. Анализ проблемы

### 1.1. Текущее состояние

Сервис `poh-demo-checkout` выполняет расчёт стоимости заказа в одной валюте:

```javascript
// src/pricing.mjs:639-643
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

**Характеристики:**
- Чистые функции без ввода-вывода
- Все значения — числа в рублях (подразумевается из констант)
- Валюта нигде не указывается явно
- Нет механизма конвертации

### 1.2. Требование

Добавить одновременный пересчёт цены в три международные валюты:
- **USD** (доллар США)
- **KZT** (тенге)
- **CNY** (юань)

Ожидаемый формат ответа не определён — открытый вопрос для архитектурных дебатов.

### 1.3. Архитектурные ограничения (из CLAUDE.md / AGENTS.md)

| Ограничение | Следствие |
|---|---|
| Арифметика — в `src/pricing.mjs` | Конвертация должна быть там же |
| Зависимостей нет | Нельзя добавлять npm-пакеты без основания |
| Новая логика → новый тест | Конвертацию нужно протестировать |
| HTTP-обёртка тонкая | Не размазывать логику по `server.mjs` |

## 2. Концепты решений

### Концепт A: Правильное — Конфигурируемая конвертация

**Суть:** Добавить параметризуемую функцию конвертации с чистыми функциями и опциональной конфигурацией через переменные окружения.

**Изменения:**
```javascript
// src/pricing.mjs
const RATES = {
  USD: Number(process.env.RATE_USD) || 0.0105,
  KZT: Number(process.env.RATE_KZT) || 4.85,
  CNY: Number(process.env.RATE_CNY) || 0.076,
};

function convert(amount, currency) {
  const rate = RATES[currency];
  if (!rate) throw new Error(`неизвестная валюта: ${currency}`);
  return Math.round(amount * rate * 100) / 100; // 2 знака
}

export function quote(items, currencies = ['RUB', 'USD', 'KZT', 'CNY']) {
  const base = { goods: subtotal(items), delivery: 0, total: 0 };
  base.delivery = deliveryFee(base.goods);
  base.total = base.goods + base.delivery;
  
  const result = { base: 'RUB', quote: {} };
  for (const curr of currencies) {
    result.quote[curr] = curr === 'RUB' 
      ? base 
      : { goods: convert(base.goods, curr), delivery: convert(base.delivery, curr), total: convert(base.total, curr) };
  }
  return result;
}
```

**Плюсы:**
- Следует архитектурным принципам (чистые функции в pricing.mjs)
- Конфигурируемость через env без зависимостей
- Обратная совместимость (можно запрашивать только RUB)
- Тестируемость (RATES можно мокать)

**Минусы:**
- Изменяет формат ответа (ломает старых клиентов)
- Округление может дать сумму ≠ товаров + доставка

**Усилия:** 2-3 часа  
**Риски:** Средние (формат ответа)

### Концепт B: Прагматичное — Расширенный ответ с фиксированными курсами

**Суть:** Минимальные изменения — добавить поля в существующий ответ с хардкодными курсами.

**Изменения:**
```javascript
// src/pricing.mjs
const RATES = { USD: 0.0105, KZT: 4.85, CNY: 0.076 };

function toCurrencies(amount) {
  return {
    RUB: amount,
    USD: Math.round(amount * RATES.USD * 100) / 100,
    KZT: Math.round(amount * RATES.KZT * 100) / 100,
    CNY: Math.round(amount * RATES.CNY * 100) / 100,
  };
}

export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  const total = goods + delivery;
  
  return {
    goods: toCurrencies(goods),
    delivery: toCurrencies(delivery),
    total: toCurrencies(total),
  };
}
```

**Плюсы:**
- Минимальные изменения кода
- Всё ещё чистые функции
- Понятная структура ответа
- Быстрая реализация

**Минусы:**
- Курсы захардкожены (требуется коммит для изменения)
- Нет конфигурируемости
- Формат ответа меняется

**Усилия:** 1-2 часа  
**Риски:** Низкие

### Концепт C: Быстрый костыль — HTTP-обёртка с постобработкой

**Суть:** Не трогать `pricing.mjs`, добавить конвертацию в `server.mjs` после вызова `quote()`.

**Изменения:**
```javascript
// src/server.mjs
const RATES = { USD: 0.0105, KZT: 4.85, CNY: 0.076 };

function convertAll(obj) {
  const result = { RUB: obj };
  for (const [curr, rate] of Object.entries(RATES)) {
    result[curr] = {
      goods: Math.round(obj.goods * rate * 100) / 100,
      delivery: Math.round(obj.delivery * rate * 100) / 100,
      total: Math.round(obj.total * rate * 100) / 100,
    };
  }
  return result;
}

// В обработчике /quote:
return send(res, 200, convertAll(quote(body?.items)));
```

**Плюсы:**
- Минимальные изменения в логике расчёта
- `pricing.mjs` остаётся нетронутым
- Быстрая реализация

**Минусы:**
- **Нарушает архитектурное правило** (логика в обёртке, не тестируется)
- Невозможно протестировать конвертацию без поднятия HTTP
- Логика размазана по модулям

**Усилия:** 30-60 минут  
**Риски:** Высокие (архитектурное нарушение)

### Концепт D: «Не трогай» — Делегирование клиенту

**Суть:** Не менять сервис, передавать responsibility за конвертацию клиенту.

**Реализация:** Не требуется никаких изменений кода.

**Аргументация:**
- Сервис остаётся простым (demo-стенд контура, а не реальный прод)
- Клиенты сами знают нужные курсы и формат
- Конвертация — задача представления, не бизнес-логики

**Плюсы:**
- Ноль изменений в коде
- Ноль рисков
- Следует принципу «минимальных изменений»

**Минусы:**
- Не решает явное требование Issue
- Каждый клиент будет реализовывать конвертацию по-своему

**Усилия:** 0 часов  
**Риски:** Нулевые, но и значение — нулевое

### Концепт E: Креативный хак — Query-параметр currencies

**Суть:** Добавить опциональный query-параметр `?currencies=USD,KZT,CNY` для запроса конвертации.

**Изменения:**
```javascript
// src/server.mjs
if (req.url === '/quote' && req.method === 'POST') {
  const url = new URL(req.url, `http://${req.headers.host}`);
  const currencies = url.searchParams.get('currencies')?.split(',') || ['RUB'];
  // ...
  return send(res, 200, quote(body?.items, currencies));
}
```

**Плюсы:**
- Обратная совместимость (по умолчанию RUB)
- Гибкость для клиентов
- Архитектурно чисто (логика в pricing.mjs)

**Минусы:**
- Смешивает POST и query-параметры
- Требует изменений и в server.mjs, и в pricing.mjs
- Более сложная реализация

**Усилия:** 2-3 часа  
**Риски:** Средние

## 4. Открытые вопросы для архитектурных дебатов

1. **Формат ответа:** Вложенный (`quote: { RUB: {...}, USD: {...} }`) или плоский (`{ goods: {...}, delivery: {...}, total: {...} }`)?

2. **Обратная совместимость:** Должен ли старый клиент продолжать работать без изменений?

3. **Курсы валют:** Фиксированные (хардкод) или конфигурируемые (env)? Стоит ли предусматривать обновление курсов без пересборки?

4. **Округление:** Как округлять (Math.floor, Math.round, до скольких знаков)?

## Архитектурные дебаты

**Дата проведения:** 2026-08-19
**Участники:** Архитектор vs Адвокат Дьявола
**Стартовая позиция:** Концепт B (Прагматичное)

### Раунд 1: Защита концепта

**Архитектор (за Концепт B):**

1. **Соответствие назначению** — репозиторий является demo-стендом контура производства (из Git-workflow и `DEMO.md`). Для демонстраций фиксированные курсов достаточны.

2. **Архитектурная чистота** — логика в `src/pricing.mjs`, чистыми функциями. Следует правилу из `CLAUDE.md`:
   > Арифметика — в `src/pricing.mjs`, чистыми функциями. `src/server.mjs` только разбирает запрос.

3. **Отсутствие зависимостей** — не требует npm-пакетов, соответствует ограничению:
   > Зависимостей у сервиса нет. Новая заводится, только если задачу нечем закрыть из стандартной библиотеки.

4. **Тестируемость** — конвертацию можно протестировать в `tests/pricing.test.mjs` без HTTP.

**Адвокат Дьявола (против):**

**К1. Формат ответа ломает обратную совместимость**
Концепт меняет `{goods, delivery, total}` на `{goods: {RUB, USD, ...}, ...}`. Старый клиент, ожидающий `quote.goods` как число, получит объект.

**К2. Жёстко захардкоженные курсы**
```javascript
const RATES = { USD: 0.0105, KZT: 4.85, CNY: 0.076 };
```
Для изменения нужен коммит. Почему не env-конфигурация заранее? Это копейки.

**К3. Округление не определено**
```javascript
Math.round(amount * RATES.USD * 100) / 100;
```
Если `goods = 1000`, `delivery = 50`:
- `goods_usd = 10.50`
- `delivery_usd = 0.53` (после округления)
- Сумма округлённых ≠ округление суммы. Как правильно?

**К4. Почему не Концепт D?**
Делегирование клиенту имеет нулевые риски. Клиенты сами знают курсы. Для демонстраций клиенты близки к разработчикам — зачем усложнять сервис?

### Раунд 2: Пересмотр

**Архитектор (усиление позиции):**

**Отв. на К1 (формат):**
Принимаю риск. Варианты:
- Versioning API (`/quote/v2`) — избыточно для demo
- Query-параметр `?format=multi` (Концепт E)
- Принять разрыв — для demo-стенда приемлемо

**Выбор:** Вариант 3 (принять разрыв), зафиксировать в требованиях.

**Отв. на К2 (env):**
Справедливо. Усиливаю концепт:

```javascript
const RATES = {
  USD: Number(process.env.RATE_USD) || 0.0105,
  KZT: Number(process.env.RATE_KZT) || 4.85,
  CNY: Number(process.env.RATE_CNY) || 0.076,

```

Гибрид B + A: простота B, конфигурируемость A.

**Отв. на К3 (округление):**
Определяю явно:
- Округление: `Math.round(x * 100) / 100` (2 знака)
- Порядок: конвертировать каждое поле отдельно, **не** гарантировать `goods + delivery = total` после конвертации

**Отв. на К4 (почему не D):**
Концепт D не решает требование Issue #11:
> Пользователь требует добавить возможность одновременного показа цены в базовой валюте и её пересчёта

Делегирование = «не делать», а требование = «сделать на сервисе».

**Адвокат Дьявола (проверка на будущее):**

**П1. Курсы устареют** — даже с env, кто-то обновляет вручную. Не появится ли требование на API для автоматического обновления? Если да — понадобятся зависимости, концепт ломается.

**П2. Много клиентов** — разные клиенты захотят разные курсы. Env глобальны. Нужен запрос с курсами от клиента (ближе к Концепту E, но не query).

**П3. Новые валюты** — добавление EUR потребует кода. Не лучше ли параметризуемый реестр валют?

**П4. Округление для KZT** — тенге обычно требуют 0 знаков (целые), а не 2. Концепт использует единое округление для всех валют.

### Модификации к Концепту B:

1. **Env-конфигурация курсов** (заимствовано из Концепта A)
   ```javascript
   const RATES = {
     USD: Number(process.env.RATE_USD) || 0.0105,
   ```

   - USD, CNY: 2 знака (`Math.round(x * 100) / 100`)
   - KZT: 0 знаков (`Math.round(x)`)

3. **Документация рисков** в коде:
   ```javascript
   // TODO: при расширении на новые валюты — параметризуемый реестр валют

   ```

4. **Фиксация в системных требованиях:**
   - Формат ответа меняется
   - Обратная совместимость не гарантируется
   - Округление: 2 знака для USD/CNY, 0 знаков для KZT

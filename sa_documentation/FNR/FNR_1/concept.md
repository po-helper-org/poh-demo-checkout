## Метаданные

- **Задача:** FNR-1: Пересчёт цены в международную валюту
- **Источник:** Issue #11
- **Дата анализа:** 2026-08-19
- **Статус:** Выбор подхода

## Краткое описание задачи

Показывать цену одновременно в базовой валюте (RUB) и конвертированной в USD, KZT, CNY при демонстрации клиенту. Текущая система работает только с рублями.

## Концепт 1: Прагматичное решение (Рекомендуемый MVP)

### Суть

Добавить минимально достаточную функциональность конвертации без изменения существующей архитектуры. Конвертация происходит на уровне `pricing.mjs` чистой функцией, курсы валют — константы в том же файле.

### Изменяемые компоненты

**Файл: `src/pricing.mjs`**

```javascript
// Курсы валют (RUB → целевая валюта)
export const RATES = {
  USD: 0.0105,  // 1 RUB = 0.0105 USD (~95 RUB/USD)
  KZT: 4.75,    // 1 RUB = 4.75 KZT (~0.21 RUB/KZT)
  CNY: 0.078,   // 1 RUB = 0.078 CNY (~12.8 RUB/CNY)
};

/**
 * Конвертация суммы из рублей в целевую валюту.
 * @param {number} amountRub — сумма в рублях
 * @param {string} currency — код валюты (USD, KZT, CNY)
 */
export function convertToCurrency(amountRub, currency) {
  const rate = RATES[currency];
  if (!rate) throw new Error(`неподдерживаемая валюта: ${currency}`);
  
  // Округление до 2 знаков для представления, но возвращаем число
  return Math.round(amountRub * rate * 100) / 100;
}

/**
 * Расширенный расчёт с конвертацией.
 * @param {Item[]} items
 * @param {string[]} currencies — список валют для конвертации
 */
export function quoteMulti(items, currencies = ['USD', 'KZT', 'CNY']) {
  const baseQuote = quote(items);
  const converted = {};
  
  for (const currency of currencies) {
    converted[currency] = {
      goods: convertToCurrency(baseQuote.goods, currency),
      delivery: convertToCurrency(baseQuote.delivery, currency),
      total: convertToCurrency(baseQuote.total, currency),
    };
  }
  
  return { ...baseQuote, converted };
}
```

**Файл: `src/server.mjs`**

```javascript
// Расширить обработку /quote:
if (req.url === '/quote' && req.method === 'POST') {
  // ...
  const multi = body?.currencies !== false; // по умолчанию — true
  const result = multi 
    ? quoteMulti(body?.items, body?.currencies || ['USD', 'KZT', 'CNY'])
    : quote(body?.items);
  return send(res, 200, result);
}
```

### Плюсы

- **Минимальные изменения** — не ломает существующий код
- **Тестируемость** — чистые функции, легко покрыть тестами
- **Без внешних зависимостей** — курсы хранятся как константы
- **Обратная совместимость** — старый формат ответа доступен
- **Соответствие архитектуре** — логика в pricing.mjs, сервер — тонкая обёртка

### Минусы

- Курсы фиксированы — требуют деплоя для обновления
- Добавление валюты требует изменения кода
- Нет истории курсов

### Оценка усилий

- **Тестирование:** 1-2 часа
- **Риски:** Низкие

## Концепт 2: Быстрый костыль (Для экстренного демо)

### Суть

Конвертация происходит на уровне HTTP-сервера после расчёта. Логика минимальна, не затрагивает `pricing.mjs`.

### Изменяемые компоненты

**Только `src/server.mjs`**

```javascript
// Жёстко прописанные курсы в server.mjs
const RATES = {
  USD: 0.0105,
  KZT: 4.75,
  CNY: 0.078,
};

function convertResponse(quote) {
  const result = { RUB: quote };
  
  for (const [currency, rate] of Object.entries(RATES)) {
    result[currency] = {
      goods: Math.round(quote.goods * rate * 100) / 100,
      delivery: Math.round(quote.delivery * rate * 100) / 100,
      total: Math.round(quote.total * rate * 100) / 100,
    };
  }
  
  return result;
}

// В обработчике /quote:
return send(res, 200, convertResponse(quote(body?.items)));
```

### Плюсы

- **Самый быстрый** — меняется один файл
- **Не трогает ядро** — pricing.mjs остаётся неизменным
- **Просто откатить** — один revert

### Минусы

- **Нарушает архитектуру** — бизнес-логика в HTTP-слое
- **Не тестируется** — конвертация вне зоны тестов
- **Невозможно переиспользовать** — функция недоступна извне

### Оценка усилий

- **Реализация:** 30-60 минут
- **Тестирование:** 0 часов (вручную через curl)
- **Риски:** Средние

### Риски

- Логика не покрыта тестами
- Архитектурное загрязнение

## Концепт 3: Правильное решение (Архитектурно выверенное)

### Суть

Введение полноценной абстракции для работы с деньгами и валютами. Создаётся отдельный модуль `src/currency.mjs` с типизированными объектами Money иCurrencyService.

### Изменяемые компоненты

**Новый файл: `src/currency.mjs`**

```javascript
/**
 * Представление денежной суммы с валютой.
 * @class Money
 */
export class Money {
  #amount;
  #currency;

  constructor(amount, currency = 'RUB') {
    this.#amount = this.#validate(amount);
    this.#currency = this.#validateCurrency(currency);
  }

  #validate(amount) {
    if (!Number.isFinite(amount) || amount < 0) {
      throw new Error(`некорректная сумма: ${amount}`);
    }
    return Math.round(amount * 100) / 100; // до копеек
  }

  #validateCurrency(currency) {
    const supported = ['RUB', 'USD', 'KZT', 'CNY'];
    if (!supported.includes(currency)) {
      throw new Error(`неподдерживаемая валюта: ${currency}`);
    }
    return currency;
  }

  get amount() { return this.#amount; }
  get currency() { return this.#currency; }

  /**
   * Конвертация в другую валюту.
   */
  convertTo(targetCurrency, rateService) {
    if (this.#currency === targetCurrency) return this;
    
    const rate = rateService.getRate(this.#currency, targetCurrency);
    const converted = this.#amount * rate;
    return new Money(converted, targetCurrency);
  }

  toJSON() {
    return { amount: this.#amount, currency: this.#currency };
  }
}

/**
 * Сервис работы с курсами валют.
 * @class CurrencyRateService
 */
export class CurrencyRateService {
  #rates = new Map();

  constructor() {
    // Базовые курсы (RUB → X)
    this.#rates.set('RUB-USD', 0.0105);
    this.#rates.set('RUB-KZT', 4.75);
    this.#rates.set('RUB-CNY', 0.078);
  }

  getRate(from, to) {
    const key = `${from}-${to}`;
    const rate = this.#rates.get(key);
    
    if (!rate) {
      throw new Error(`нет курса для ${key}`);
    }
    return rate;
  }

  updateRate(from, to, rate) {
    const key = `${from}-${to}`;
    this.#rates.set(key, rate);
  }
}

/**
 * Фабрика для создания Money-объектов.
 */
export const money = (amount, currency = 'RUB') => new Money(amount, currency);
```

**Файл: `src/pricing.mjs` — рефакторинг**

```javascript
import { money, CurrencyRateService } from './currency.mjs';

const rateService = new CurrencyRateService();

export function quoteMulti(items, currencies = ['USD', 'KZT', 'CNY']) {
  const baseQuote = quote(items);
  
  const result = {
    RUB: {
      goods: money(baseQuote.goods),
      delivery: money(baseQuote.delivery),
      total: money(baseQuote.total),
    }
  };
  
  for (const currency of currencies) {
    result[currency] = {
      goods: result.RUB.goods.convertTo(currency, rateService),
      delivery: result.RUB.delivery.convertTo(currency, rateService),
      total: result.RUB.total.convertTo(currency, rateService),
    };
  }
  
  return result;
}
```

### Плюсы

- **Правильная архитектура** — чистая абстракция
- **Типобезопасность** — Money-объекты нельзя confuse
- **Расширяемость** — легко добавить новые функции
- **Переиспользуемость** — Money доступен везде

### Минусы

- **Большой объём изменений** — рефакторинг ядра
- **Сложнее тестировать** — больше кода
- **Over-engineering** для текущей задачи

### Оценка усилий

- **Реализация:** 1-2 дня
- **Тестирование:** 1 день
- **Риски:** Средние (большая зона изменений)

### Риски

- Регрессия в существующих тестах
- Сложность отладки при ошибках

## Концепт 4: Конфигурируемое решение (Гибкость)

### Суть

Курсы валют выносятся в конфигурационный файл (JSON или environment variables), что позволяет менять их без перекомпиляции кода.

### Изменяемые компоненты

**Новый файл: `config/currencies.json`**

```json
{
  "base": "RUB",
  "rates": {
    "USD": 0.0105,
    "KZT": 4.75,
    "CNY": 0.078
  }
}
```

**Файл: `src/pricing.mjs`**

```javascript
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const __dirname = dirname(fileURLToPath(import.meta.url));
const configPath = join(__dirname, '../config/currencies.json');

let cachedConfig;

function loadConfig() {
  if (cachedConfig) return cachedConfig;
  try {
    cachedConfig = JSON.parse(readFileSync(configPath, 'utf8'));
    return cachedConfig;
  } catch {
    // Fallback на дефолтные курсы
    return {
      base: 'RUB',
      rates: { USD: 0.0105, KZT: 4.75, CNY: 0.078 }
    };
  }
}

export function convertToCurrency(amountRub, currency) {
  const config = loadConfig();
  const rate = config.rates[currency];
  if (!rate) throw new Error(`неподдерживаемая валюта: ${currency}`);
  return Math.round(amountRub * rate * 100) / 100;
}
```

### Плюсы

- **Гибкость** — курсы можно менять без деплоя
- **Разделение конфигурации и кода** — следуем best practices
- **Fallback** — есть дефолтные значения

### Минусы

- **Зависимость от файловой системы** — нарушение принципа "без зависимостей"
- **Сложнее** — чем просто константы
- **Холодный старт** — чтение файла при каждом запросе (если без кеширования)

### Оценка усилий

- **Реализация:** 3-4 часа
- **Тестирование:** 2 часа
- **Риски:** Низкие

### Риски

- Ошибки парсинга конфигурации
- Файловая система unavailable в некоторых окружениях

## Раунд 1: Защита

### Архитектор: Защита Концепта 1 (Прагматичное решение)

Я защищаю **Концепт 1** как оптимальный выбор для текущей задачи. Обоснование:

**1. Соответствие архитектуре проекта**
Анализ `src/pricing.mjs` (строки 1-53) показывает:
- Весь код — чистые функции без сайд-эффектов
- Комментарий явно разделяет concerns: "Чистые функции без ввода-вывода: цена — то, что проверяется тестом"
- Добавление `convertToCurrency` и `quoteMulti` продолжит эту традицию

Концепт 1 не нарушает существующий паттерн: новая логика остаётся в `pricing.mjs` как чистые функции.

**2. Соответствие ограничению "без внешних зависимостей"**
CI-конфиг (`.github/workflows/ci.yml`, строки 69-70) гласит:
> "Зависимостей у сервиса нет намеренно — это его свойство, а не упущение"

Концепт 4 с файловой системой (`fs.readFileSync`) нарушает это ограничение. Концепт 1 уважает его: курсы — константы в коде.

**3. Покрытие тестами**
Текущий `tests/pricing.test.mjs` проверяет все функции из `pricing.mjs`. Концепт 1 предлагает добавить тесты для `convertToCurrency` и `quoteMulti` — продолжение существующей практики.

Концепт 2 ("Быстрый костыль") выносит логику в `server.mjs`, который тесты не покрывают — это regress risk.

**4. Обратная совместимость**
`src/server.mjs` (строки 29-43) показывает простую обработку `/quote`. Концепт 1 предлагает:
```javascript
const multi = body?.currencies !== false;
const result = multi ? quoteMulti(body?.items, body?.currencies) : quote(body?.items);
```
Старый формат (`currencies=false`) сохраняется. Это backwards compatible.

### Адвокат Дьявола: Атака на Концепт 1

Я оспариваю выбор Концепта 1. Проблемы:

**1. Жёстко захардкоженные курсы — это техдолг**
```javascript
export const RATES = {
  USD: 0.0105,  // Хардкод!
  KZT: 4.75,
  CNY: 0.078,
};
```
Курсы валют меняются ежедневно. Обновление потребует:
- Коммита в репозиторий
- Code review
- Деплоя сервиса

Это не MVP, это костыль, который станет production reality.

**2. Концепт 3 (Правильное решение) недооценён**
Вы отвергаете Концепт 3 как "over-engineering", но задача — работа с деньгами. Деньги требуют точности:
- `Money`-класс предотвращает confuse между RUB и USD
- Валидация в конструкторе защищает от некорректных данных
- `CurrencyRateService` — абстракция для будущих требований

Отказ от правильной абстракции сейчас == рефакторинг позже под давлением production.

**3. Edge-кейсы не проработаны**
Концепт 1 не решает:
- Округление до 2 знаков может давать расхождения в 1 копейку при больших суммах
- Что если клиент запросит несуществующую валюту? `throw Error` — не лучший UX
- Нет истории курсов — для аудита это проблема

Концепт 3 с `Money`-классом решает это структурно.

**4. "Прагматичность" — это синоним "плохо, но быстро"**
Концепт 2 ("Быстрый костыль") честно называется костылём. Концепт 1 называется "прагматичным", но по сути — тот же костыль, только в более дорогом файле.

## Раунд 2: Пересмотр

### Архитектор: Ответ на критику

**1. Про хардкод курсов**
Да, курсы захардкожены. Но:
- Задача — **демо-сценарий**, не production
- Issue #11 (согласно `task.md`, строка 13) — "при демонстрации клиенту"
- После успешного HowToDemo можно перейти к Концепту 3 или 4

Это не техдолг, это intentional compromise для проверки гипотезы.

**2. Про Концепт 3**
Концепт 3 — архитектурно правильный, но:
- Оценка: 1-2 дня реализации + 1 день тестирования
- Зона изменений: рефакторинг `pricing.mjs` + новый `currency.mjs`
- Risk: регрессия в существующих тестах

Для демо-сценария это over-investment. Концепт 1 — 2-3 часа.

**3. Про edge-кейсы**
Округление до 2 знаков — это в Концепте 1, и в Концепте 3. `Math.round(x * 100) / 100` — стандартный подход.

Несуществующая валюта — `throw Error` в обоих концептах. Концепт 3 не решает это лучше.

История курсов — не в scope демо-сценария.

**4. Про "прагматичность" vs "костыль"**
Разница:
- Концепт 2: логика в `server.mjs` (HTTP-слой), не тестируется
- Концепт 1: логика в `pricing.mjs` (бизнес-слой), тестируется

Это не "плохо, но быстро", это "хорошо, и достаточно быстро".

### Адвокат Дьявола: Проверка на прочность

**1. А что если через полгода курс изменится на 20%?**
Концепт 1: деплой. Концепт 4: правка JSON-файла. Разница — в скорости реакции.

Вы отвергли Концепт 4 из-за "зависимости от файловой системы", но:
- Чтение конфига при старте — не зависимость, а практика
- Fallback на дефолтные курсы — safety net

**2. А что если бизнес добавит ещё 10 валют?**
Концепт 1: расширить `RATES` объект, править код. Концепт 3/4: просто добавить пару ключ-значение.

MVP сегодня == requirement завтра. Концепт 1 не масштабируется.

**3. А что если понадобится динамическое обновление курсов?**
Концепт 1/4: архитектура не поддерживает. Концепт 3: `CurrencyRateService.updateRate()` — уже есть интерфейс.

Вы спорите с future requirement, который уже visible в horizon.

## Раунд 3: Вердикт

### Архитектор: Итоговая позиция

Концепт 1 остаётся моим выбором для **текущей задачи (демо-сценарий)**:

1. **Time-to-value:** 2-3 часа vs 2-3 дня (Концепт 3)
2. **Risk:** низкий (малая зона изменений) vs средний
3. **Architecture compliance:** логика там, где положено (`pricing.mjs`)
4. **Testability:** полностью покрывается существующим тестовым фреймворком

Я признаю:
- Концепт 3 — правильное долгосрочное решение
- Концепт 4 — более гибкий для production

Но для FNR-1 (демо) Концепт 1 — оптимальный баланс усилий/рисков/качества.

**Предложение:** реализовать Концепт 1, пройти HowToDemo, затем в SubIssue вынести рефакторинг на Концепт 3.

### Адвокат Дьявола: Итоговая позиция

Я признаю defeat в части **демо-сценария**:

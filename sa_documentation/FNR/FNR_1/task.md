# Скидка по промокоду в корзине

## Категория задачи
Новая функциональность (feature)

## Источник
Issue po-helper-org/poh-demo-checkout#64

## Контекст (AS IS)

### Текущее состояние сервиса
Сервис расчёта стоимости заказа `poh-demo-checkout` предоставляет эндпоинт `POST /quote`, который принимает массив товаров и возвращает структуру `{ goods, delivery, total }` ([src/server.mjs:711-728](src/server.mjs:711-728)).

**Архитектурное разделение:** Арифметика изолирована в `src/pricing.mjs` чистыми функциями ([src/pricing.mjs:3-5](src/pricing.mjs:3-5)), HTTP-обёртка в `src/server.mjs` только разбирает запрос и отдаёт коды ([src/server.mjs:2-4](src/server.mjs:2-4)).

**Текущий расчёт:**
- `quote(items)` → `subtotal(items)` → `goods` ([src/pricing.mjs:49](src/pricing.mjs:49))
- `deliveryFee(goods)` → `delivery` ([src/pricing.mjs:50](src/pricing.mjs:50))
- `total = goods + delivery` ([src/pricing.mjs:51](src/pricing.mjs:51))

### Что касается промокодов
Поиск по кодовой базе (`discount`, `promo`, `coupon`, `SALE10`) не дал результатов — механизма промокодов не существует ([repowise-dialog.md:9](sa_documentation/FNR/FNR_1/repowise-dialog.md:9)).

### Валидация
`subtotal()` проверяет массив на пустоту, положительность цены, целочисленность количества ([src/pricing.mjs:21-34](src/pricing.mjs:21-34)).

### Тестовый охват
8 тестов покрывают `subtotal`, `deliveryFee`, `quote` ([tests/pricing.test.mjs:1-52](tests/pricing.test.mjs:1-52)). Тестов для скидок нет — функционала нет.

## Проблема (Gap)

Отсутствует механизм применения промокодов для скидки на сумму товаров. Маркетинг не может запускать акции без изменения кода.

**Требования из Issue:**
1. Поле ввода промокода в корзине (frontend, вне scope данной задачи)
2. Код `SALE10` даёт 10% скидки на сумму товаров
3. Неизвестный код — понятное сообщение, сумма не меняется
4. Применённая скидка видна отдельной строкой в итогах
5. **Доставка не скидывается**

## Доказательства (Code Proofs)

### Доказательство 1: Текущая структура ответа API
```javascript
// src/pricing.mjs:48-52
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```
**Интерпретация:** Возврат `{ goods, delivery, total }` — скидка требует нового поля `discount` и пересчёта `total`.

### Доказательство 2: Обращение к quote из HTTP-слоя
```javascript
// src/server.mjs:724
return send(res, 200, quote(body?.items));
```
**Интерпретация:** HTTP-слой передаёт только `items`. Для промокода нужно добавить `promoCode` из тела запроса.

### Доказательство 3: Константы доставки
```javascript
// src/pricing.mjs:6-9
export const DELIVERY_FEE = 300;
export const FREE_DELIVERY_FROM = 3000;
```
**Интерпретация:** Бесплатная доставка от 3000₽. Скидка на товары не должна влиять на порог — доставка считается по `goods` до применения скидки.

### Доказательство 4: Отсутствие механизма скидок
```javascript
// src/pricing.mjs — полный файл (52 строки)
// Нет ни одной константы, функции или логики, связанной с promo/discount
```
**Интерпретация:** Функционал нужно добавлять с нуля.

## Границы (In/Out Scope)

### В scope (MVP)
- Приём промокода в API (`POST /quote` с полем `promoCode`)
- Хардкод `SALE10` → 10% скидки на товары
- Неизвестный промокод → понятное сообщение, сумма не меняется
- Поле `discount` в ответе API
- Пересчёт `total = goods - discount + delivery`

### Out scope (на следующие итерации)
- UI для ввода промокода (frontend)
- Управление промокодами для маркетинга (admin panel, database)
- Типы скидок кроме процентных (фиксированная сумма, "2+1", бесплатная доставка)
- Ограничения промокодов (срок действия, минимальная сумма, однократность)
- Кумулятивные промокоды

## Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Изменение контракта `quote()` сломает существующих клиентов | Высокое | Сохранить обратную совместимость: `promoCode` — опциональное поле |
| Скидка рассчитывается на `goods` после применения промокода → нарушает требование "доставка не скидывается" | Среднее | Доставка считать по `goods` ДО применения скидки (текущее поведение) |
| Отсутствие тестов → регрессия в будущем | Среднее | Добавить тесты для всех веток (валидный, невалидный, без промокода) |

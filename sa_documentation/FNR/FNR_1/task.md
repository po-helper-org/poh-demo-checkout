# FNR-1: Запрос на изменение визуальной стилистики в проекте без UI

## Статус

**Тип:** Новая фича (запрос на создание UI)  
**Критичность:** P3 (Impact 3/5, Time criticality 1/5, Risk reduction 1/5)  
**Источник:** Issue #8

## Описание проблемы

Пользователь запросил изменение визуальной стилистики интерфейса под дизайн приложения Threads: "Хочу чтобы весь визуал выглядел как в Threads".

### Диагноз: Отсутствие предмета изменения

**Факт:** В проекте отсутствует визуальный интерфейс (UI).

**Доказательства:**

1. **Состав проекта** (repomix-output.xml:42-60):
   ```
   src/
     pricing.mjs    # логика расчёта стоимости
     server.mjs     # HTTP-обёртка
   tests/
     pricing.test.mjs
   ```
   Отсутствуют директории `frontend/`, `web/`, `client/`, `static/`, `public/`, `assets/`.

2. **Отсутствие UI-файлов:**
   - Нет файлов `.html`, `.css`, `.jsx`, `.tsx`, `.vue`, `.svelte` (проверка по grep)
   - Нет файлов со стилями: `grep -r "color\|background\|style" src/` — пустой результат

3. **Архитектура сервиса** (server.mjs:1-55):
   - Чистый HTTP-JSON API без фронтенда
   - Единственные endpoint'ы: `/healthz`, `/quote`
   - Ответы — JSON без HTML-рендеринга

**Вывод:** Запрос не может быть выполнен как изменение существующего кода, потому что визуального интерфейса в проекте нет.

## Варианты интерпретации запроса

| Вариант | Описание | Обоснование |
|---------|----------|-------------|
| 1. Создание нового UI | Пользователь хочет добавить веб-интерфейс к существующему API | Наиболее вероятно: "весь визуал" подразумевает полный интерфейс для сервиса |
| 2. Ошибочный запрос | Пользователь перепутал проекты | Маловероятно: Issue заведён в данном репозитории |
| 3. CLI/TUI интерфейс | Текстовый интерфейс в стиле Threads | Противоречит "визуал" и ссылке на GUI-приложение |

## Границы системы (как есть)

**Компоненты:**
- `src/pricing.mjs:19-59` — чистая бизнес-логика (расчёт стоимости заказа)
- `src/server.mjs:26-46` — HTTP-обёртка (endpoint `/quote`)
- `tests/pricing.test.mjs` — покрытие логики расчёта

**Отсутствует:**
- Любой слой представления (presentation layer)
- Статические файлы (HTML/CSS/JS)
- Шаблоны рендеринга
- Система стилизации/тем

## Ограничения

1. **Без зависимостей:** Проект намеренно не использует сторонние библиотеки (проверка в package.json)
2. **Простота сервиса:** Это демо-стенд контура производства, а не полноценный продукт

## Рекомендация

Перед принятием решения о реализации необходимо уточнить у пользователя:

1. Требуется ли создать веб-интерфейс для текущего API?
2. Если да — какой минимальный набор функций должен быть реализован (MVP)?
3. Если нет — в каком проекте подразумевалось изменение визуала?

## Краткое описание (Summary)

Необходимо добавить маршрут `GET /version`, возвращающий версию сервиса из `package.json`. Текущий эндпоинт `/healthz` не идентифицирует версию кода, что затрудняет разбор выкладок.

---

## Диагноз проблемы

### Симптом

По живому сервису невозможно определить версию работающего кода без доступа внутрь контейнера. Метка образа и лог старта недостоверны: образ пересобирается молча, строка «сервис запущен» идентична для всех версий.

### Корневая причина

В `src/server.mjs` отсутствует маршрут, предоставляющий информацию о версии [`server.mjs:39-94`](src/server.mjs:39-94). Единственный информационный эндпоинт `/healthz` возвращает только `status` и `uptime_sec` [`server.mjs:43-50`](src/server.mjs:43-50), но не идентификатор версии.

### Доказательства

| Факт | Источник |
|------|----------|
| Версия сервиса хранится в `package.json` как `0.1.0` | [`package.json:3`](package.json:3) |
| `/healthz` реализует паттерн 405 для не-GET запросов | [`server.mjs:43-50`](server.mjs:43-50) |
| Сервис не имеет зависимостей (section `dependencies` отсутствует) | [`package.json:1-14`](package.json:1-14) |

| Тесты для 405 уже существуют для `/healthz` | [`tests/server.test.mjs:163-182`](tests/server.test.mjs:163-182) |

## Контекст и ограничения

### Технический контекст

**Архитектура чтения `package.json`:**

Сервис не имеет внешних зависимостей. Для чтения версии есть два варианта:

1. **ES-импорт JSON (рекомендуется):**
   ```javascript
   import packageJson from '../package.json' with { type: 'json' };
   const version = packageJson.version;
   ```
2. **`fs.readFile` при старте с кешированием** — требует обработки ошибок и Zustand-хранения.

**Паттерн 405 Method Not Allowed:**

Эндпоинт `/healthz` уже реализует требуемый шаблон [`server.mjs:43-50`](server.mjs:43-50):
- Проверка метода: `if (req.method !== 'GET')`
- Ответ 405 с `{ error: 'Method Not Allowed' }`
- Заголовок `Allow: GET`

Новый эндпоинт `/version` должен следовать этому же паттерну.

**Паттерны тестирования:**

- Вспомогательная функция `request()` в `tests/server.test.mjs` симулирует HTTP без поднятия реального сервера [`tests/server.test.mjs:15-81`](tests/server.test.mjs:15-81)
- Тесты 405 для `/healthz` покрывают POST, PUT, DELETE [`tests/server.test.mjs:163-182`](tests/server.test.mjs:163-182)
- Аналогичные тесты требуются для `/version`

### Ограничения

| Ограничение | Деталь |
|-------------|--------|
| Без новых зависимостей | Сервис не имеет зависимостей — не добавлять |
| `/healthz` не меняется | Версия отдаётся отдельным маршрутом |
| `pricing.mjs` не трогается | Зона изменений — только `server.mjs` и тесты |
| Метод только GET | Другие методы отвечают 405 |
| Версия из `package.json` | Не дублировать константой в коде |

## Что нужно сделать (Scope)

### 1. Добавить маршрут `/version` в `src/server.mjs`

**Требования к реализации:**

- Маршрут обрабатывает `pathname === '/version'`
- При методе `GET`: ответ 200, тело `{"version": "<версия>"}`
- При методах != `GET`: ответ 405, заголовок `Allow: GET`
- Версия читается из `package.json`, не хардкодится

**Расположение кода:**

Между существующими маршрутами, например после `/healthz` [`server.mjs:43-51`](server.mjs:43-51).

### 2. Добавить тесты в `tests/server.test.mjs`

**Минимальный набор тестов:**

1. `GET /version` возвращает 200 с полем `version` равным `0.1.0`
2. `POST /version` возвращает 405 с заголовком `Allow: GET`
3. (опционально) `PUT /version` возвращает 405
4. (опционально) `DELETE /version` возвращает 405

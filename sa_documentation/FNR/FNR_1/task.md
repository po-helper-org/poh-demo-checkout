# Задача: Счётчик посещений и успешных транзакций

**Issue:** #90
**Статус:** анализ завершён
**Дата:** 2026-08-21

---

## Контекст

Сервис `poh-demo-checkout` — HTTP-сервер расчёта стоимости заказа с двумя эндпоинтами:
- `GET /healthz` — health check
- `POST /quote` — расчёт стоимости заказа по позициям и опциональному промокоду

Текущая реализация не обеспечивает ни подсчёта запросов, ни фиксации успешных операций. Отсутствует какая-либо телеметрия или метрики эксплуатации.

---

## Текущее состояние (AS IS)

### Что существует сейчас

| Компонент | Реализация | Доказательство |
|-----------|------------|----------------|
| HTTP-сервер | `src/server.mjs` с функцией `app()` | server.mjs:26 |
| Эндпоинт расчёта | `POST /quote` вызывает `quote()` | server.mjs:44 |
| Логирование | Только `console.log` при старте сервера | server.mjs:52 |
| Счётчики посещений | Отсутствуют | — |
| Счётчики транзакций | Отсутствуют | — |
| Хранилище метрик | Отсутствует | — |
| Внешние зависимости | Отсутствуют (только stdlib) | package.json |

### Поток обработки запроса

```
POST /quote → app() → readJson() → quote() → send(res, 200, {...})
                  ↓              ↓             ↓
                 (1)            (2)           (3)
```

Где:
- **(1)** точка входа — каждый POST `/quote`
- **(2)** валидация и расчёт — может выбросить исключение
- **(3)** успешный ответ — HTTP 200 с объектом `{ goods, delivery, discount, promoStatus, total }`

Health-чек `GET /healthz` не считается посещением.

---

## Проблема

Система не предоставляет возможности:
1. **Подсчитать количество посещений** — запросов к эндпоинту `/quote`
2. **Подсчитать количество успешных транзакций** — запросов, завершившихся HTTP 200

Это означает:
- Отсутствует видимость нагрузки на сервис
- Нельзя оценить успешность обработки запросов
- Нет данных для мониторинга эксплуатации

## Требования

### Функциональные требования (ФТ)

| ID | Описание | Критерий выполнения |
|----|----------|---------------------|
| ФТ-1 | Система фиксирует каждое посещение на вход | При каждом запросе `POST /quote` счётчик посещений увеличивается на 1 |
| ФТ-2 | Система фиксирует каждую успешную транзакцию на выход | При каждом успешном вызове `quote()` (HTTP 200) счётчик транзакций увеличивается на 1 |
| ФТ-3 | Система предоставляет доступ к значениям счётчиков | Существует способ получить текущие значения обоих счётчиков |

### Нефункциональные требования (НФТ)

| ID | Категория | Описание |
|----|-----------|----------|
| НФТ-1 | Ограничения зависимостей | Решение должно использовать только Node.js стандартную библиотеку |
| НФТ-2 | Разделение ответственности | Арифметика счётчиков — в `server.mjs`, не в `pricing.mjs` |
| НФТ-3 | Изоляция | Health-чек `/healthz` не влияет на счётчик посещений |

### Ограничения

- **Архитектурные:** счётчики реализуются в `src/server.mjs` (HTTP-слой), логика расчёта в `pricing.mjs` не затрагивается
- **Технические:** никаких новых зависимостей в `package.json`
- **Границы MVP:** счётчики хранятся в памяти приложения; персистентность не требуется

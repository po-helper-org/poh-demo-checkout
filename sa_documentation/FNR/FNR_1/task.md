# Задача FNR-1: Пороговая скидка за объём заказа в /quote

## Статус
**Тип:** Новая функциональность (Feature Request)  
**Источник:** Issue #13  
**Дата анализа:** 2025-08-19

---

## 1. Проблема

### 1.1 Что сломано / чего не хватает

Эндпоинт `POST /quote` считает сумму позиций и доставку, но **не поддерживает скидки за объём заказа**. Крупные заказы уходят по той же цене, что и мелкие, что лишает отдел продаж автоматического рычага стимулирования больших чеков.

**Проблемный сценарий:**
- Заказ на ₽50,000 и на ₽1,000 рассчитываются по одинаковой формуле
- Единственный способ дать скидку — ручной пересчёт в переписке
- Нет автоматизации для удержания клиентов при крупных заказах

### 1.2 Контекст

**Окружение:**
- Сервис: `poh-demo-checkout` — HTTP-сервис расчёта стоимости заказа
- Технологический стек: Node.js (ES Modules), без внешних зависимостей
- Эндпоинт: `POST /quote` — возвращает JSON с полями `goods`, `delivery`, `total`

**Ограничения:**
1. **Без новых зависимостей** — сервис принципиально не использует внешние пакеты
2. **Порог доставки проверяется ДО скидки** — `FREE_DELIVERY_FROM = 3000` применяется к `goods`, а не к `goods - discount`
3. **Арифметика в `pricing.mjs`** — чистые функции, без HTTP-кода
4. **HTTP-обёртка в `server.mjs`** — только разбор запроса и коды ответов

## 2. Текущее поведение (Evidence)

### 2.1 Реализация сегодня

**Файл: `src/pricing.mjs`** (строки 607-660)

```javascript
export const DELIVERY_FEE = 300;
export const FREE_DELIVERY_FROM = 3000;

export function subtotal(items) {
  // Сумма позиций без доставки
  // ...
}

export function deliveryFee(amount) {
  return amount >= FREE_DELIVERY_FROM ? 0 : DELIVERY_FEE;
}

export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

**Файл: `src/server.mjs`** (строки 662-717)

```javascript
export const app = async (req, res) => {
  // ...
  if (req.url === '/quote' && req.method === 'POST') {
    // ...
    return send(res, 200, quote(body?.items));
  }
  // ...
};
```

### 2.2 Ответ API сегодня

**Пример запроса:**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":5000,"qty":1}]}'
```

**Ответ сегодня:**
```json
{"goods":5000,"delivery":0,"total":5000}
```

**Что отсутствует:**
- Поля `discount` в ответе
- Логика расчёта скидки по порогам
- Учёт скидки в поле `total`

## 3. Ожидаемое поведение

### 3.1 Бизнес-логика скидки

| Сумма позиций (`goods`) | Скидка |
|---|---|
| до 5000 (не включительно) | 0% |
| от 5000 до 15000 (включительно) | 5% |
| от 15000 (включительно) | 10% |

**Правила границ:**
- Границы включительные: заказ ровно на 5000 получает 5%
- Округление вниз: `discount = Math.floor(goods * rate)` (целое число рублей)
- Скидка применяется только к `goods`, доставка не дисконтируется

### 3.2 Новая структура ответа

```json
{
  "goods": 5000,
  "discount": 250,
  "delivery": 0,
  "total": 4750
}
```

**Где:**
- `goods` — сумма позиций (не меняется)
- `discount` — сумма скидки в рублях (новое поле)
- `delivery` — стоимость доставки (не меняется, считается по `goods`)
- `total` — итог к оплате: `goods - discount + delivery`

### 3.3 Критические сценарии (HowToDemo)

**Сценарий 1: Заказ ровно на порог 5% скидки**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":5000,"qty":1}]}'
```
Ожидаемо: `{"goods":5000,"discount":250,"delivery":0,"total":4750}`

**Сценарий 2: Малый заказ без скидки**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":1000,"qty":1}]}'
```
Ожидаемо: `{"goods":1000,"discount":0,"delivery":300,"total":1300}`

**Сценарий 3: Заказ на 10% скидку**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":15000,"qty":1}]}'
```
Ожидаемо: `{"goods":15000,"discount":1500,"delivery":0,"total":13500}`

### 5.1 Затронутые компоненты

| Компонент | Изменение | Обоснование |
|---|---|---|
| `src/pricing.mjs` | Новая функция `discountRate(amount)` + изменение `quote()` | Добавление логики скидки |
| `tests/pricing.test.mjs` | Новые тесты на границы порогов | Покрытие новой логики |
| `src/server.mjs` | Без изменений (автоматически подхватит новый формат ответа) | HTTP-слой не зависит от структуры ответа |

### 5.2 Обратная совместимость

**Breaking change:** Ответ API добавляет поле `discount`, что теоретически может сломать клиентов, которые проверяют точное число полей. Однако:

1. Демо-стенд не имеет внешних клиентов с жёсткими контрактами
2. Добавление поля в JSON обычно обратно совместимо
3. Поле `total` пересчитывается, старые клиты увидят новую цену

## 6. Edge-кейсы для исследования

Во время разработки обратить внимание на:

1. **Порядок применения скидки и бесплатной доставки**
   - Убедиться: доставка бесплатна при `goods >= 3000`, даже если после скидки сумма меньше
   - Пример: `goods=3000, discount=300` → доставка должна быть 0, не 300₽

2. **Округление скидки**
   - `Math.floor(4999.99 * 0.05) = 249` (не 250)
   - `Math.floor(5000 * 0.05) = 250`

3. **Пустой/битый запрос**
   - Уже покрыт текущей логикой валидации (ошибки возвращаются корректно)

4. **Отрицательная цена/количество**
   - Уже покрыт текущей валидацией в `subtotal()`

## 7. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Скидка отнимает бесплатную доставку | Средняя | Среднее | Явная проверка: `deliveryFee(goods)` вызывается до расчёта скидки |
| Ошибка в формуле расчёта total | Низкая | Высокое | Тесты на все границы порогов |
| Разрыв между `goods` и `total` (клиент не поймёт, почему `total != goods + delivery`) | Низкая | Низкое | Поле `discount` явно показывает разницу |

# Задача: FNR-1 — Оплата картой через CloudPayments в чекауте

## Статус
**Состояние:** Анализ завершён, ожидаются уточнения

## Резюме проблемы

Сервис расчёта заказа (`POST /quote`) поддерживает расчёт стоимости (товары + доставка + скидка по промокоду), но не обеспечивает возможность оплаты. Требуется добавить поддержку способа оплаты через CloudPayments — эквайринга, который бизнес уже использует в других каналах.

**Ключевое ограничение:** Внешние вызовы API CloudPayments (создание платежа, вебхуки) в данный MVP **не входят**. Сервис только подготавливает данные для инициализации клиентского виджета CloudPayments Checkout.

---

## Контекст системы

### Архитектура текущего решения

Сервис организован по принципу **разделения ответственности**:

1. **`src/pricing.mjs`** — чистые функции расчёта стоимости
   - Содержит константы: `DELIVERY_FEE = 300`, `FREE_DELIVERY_FROM = 3000`, `MIN_ORDER_AMOUNT = 1000`
   - Реестр промокодов: `PROMO_CODES`
   - Функция `quote(items, promoCode = null)` возвращает `{ goods, delivery, discount, promoStatus, total }`
   - **Важно:** Нет сетевых вызовов по замыслу — всё проверяется без сети
   - Доказательство: `src/pricing.mjs:1-3`

2. **`src/server.mjs`** — HTTP-обёртка
   - Эндпоинт `POST /quote` вызывает `quote(body?.items, body?.promoCode)`
   - Ошибки пробрасываются как HTTP 400
   - Доказательство: `src/server.mjs:29-42`

3. **`tests/pricing.test.mjs`** — тесты покрывают все сценарии промокода
   - Валидный промокод → `promoStatus: 'applied'`, скидка рассчитана
   - Невалидный промокод → `promoStatus: 'unknown'`, скидка = 0
   - Доказательство: `tests/pricing.test.mjs:74-92`

### Текущее поведение промокода

```
quote(items, 'SALE10') → { goods: 2000, delivery: 300, discount: 200, promoStatus: 'applied', total: 2100 }
quote(items, 'INVALID') → { goods: 1000, delivery: 300, discount: 0, promoStatus: 'unknown', total: 1300 }
```

**Важно:** Невалидный промокод **не вызывает ошибку** — возвращает `promoStatus: 'unknown'` с нулевой скидкой.

## Диагноз проблемы

### Что требуется

1. `POST /quote` должен принимать необязательное поле `paymentMethod`
2. Поддерживаемое значение: `"cloudpayments"`
3. При передаче валидного `paymentMethod` ответ расширяется блоком `payment`:
   ```javascript
   {
     goods: 2000,
     delivery: 300,
     discount: 0,
     total: 2300,
     payment: {
       provider: "cloudpayments",
       amount: 2300,  // равно total
       currency: "RUB",
       invoiceId: "..."  // идентификатор счёта
     }
   }
   ```
4. Без `paymentMethod` ответ остаётся прежним (обратная совместимость)
5. Невалидный `paymentMethod` → HTTP 400 с внятным текстом ошибки

### Где реализовывать

- **Формирование данных для оплаты** → чистая функция в `src/pricing.mjs`
- **Парсинг `paymentMethod` из запроса** → `src/server.mjs` (аналогично `promoCode`)
- **Валидация `paymentMethod`** → `src/pricing.mjs` (аналогично `PROMO_CODES`)

## Открытые вопросы

### 1. Противоречие в описании поведения

**Факт:** В описании задачи сказано:
> "Неизвестный `paymentMethod` — ошибка запроса, аналогично неизвестному промокоду (см. #1)"

**Факт:** В текущей реализации неизвестный промокод **НЕ вызывает ошибку**:
- `src/pricing.mjs:76-77` — возвращает `promoStatus: 'unknown'`
- `tests/pricing.test.mjs:84-92` — тест подтверждает отсутствие ошибки

**Вопрос:** Какое поведение правильное для `paymentMethod`?
- **Вариант A:** Ошибка 400 (как указано в задаче)
- **Вариант B:** Статус в ответе (как сейчас для промокода)

### 2. Генерация `invoiceId`

**Требование:** Блок `payment` должен содержать `invoiceId` — идентификатор счёта для CloudPayments.

**Вопрос:** Как генерировать `invoiceId` в рамках чистой функции?
- **Вариант A:** UUID (требует зависимости `crypto`)
- **Вариант B:** Хеш от параметров заказа
- **Вариант C:** Передавать из HTTP-слоя
- **Вариант D:** Иное

### 3. Валюта

**Факт:** Все суммы в коде hardcoded в рублях.

**Вопрос:** Нужно ли явное поле `currency: "RUB"` в блоке `payment` или валюта подразумевается?

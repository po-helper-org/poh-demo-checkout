# FNR-1: Промо-код в расчёте заказа

## Статус: Новая

**Источник:** Issue #1 (po-helper-org/poh-demo-checkout)

## Краткое описание

Эндпоинт `POST /quote` не поддерживает промо-коды: скидки считаются вручную в переписке, что приводит к расхождениям между суммой в чате и фактической оплатой.

## Детальное описание проблемы

### Что сломано

`POST /quote` принимает только поле `items` и не обрабатывает промо-коды. Расчёт ведётся только по ценам товаров без скидок.

**Код-доказательство:** `src/server.mjs:39`

```javascript
return send(res, 200, quote(body?.items));
```

Функция `quote` из `src/pricing.mjs:48` принимает только `items` и не имеет параметра для промо-кода.

**Код-доказательство:** `src/pricing.mjs:48-52`

```javascript
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

### Контекст

- Проект: `poh-demo-checkout` — демо-стенд контура производства для расчёта стоимости заказа
- Стек: Node.js >=22, vanilla JavaScript (модули ES), без внешних зависимостей
- Архитектурные ограничения:
  - Арифметика — в `src/pricing.mjs` чистыми функциями
  - `src/server.mjs` — только HTTP-обёртка, разбор запроса и коды ответов
  - Новые зависимости заводятся только при невозможности закрыть задачу стандартной библиотекой

### Последствия

1. **Финансовые расхождения:** Сумма в чате расходится с суммой в оплате
2. **Ручной труд:** Скидки считаются вручную в переписке
3. **Потеря доверия:** Продавцы и покупатели видят разные суммы

## Что требуется

### Функциональные требования

1. **Новый параметр запроса:** `POST /quote` должен принимать необязательное поле `promo` — строку кода скидки
2. **Валидация промо-кода:**
   - Известный код → процент скидки от суммы товаров
   - Неизвестный код → HTTP 400 с внятным текстом ошибки
3. **Расширение ответа:** Добавить поле `discount` — сумма скидки в рублях
4. **Обновлённый `total`:** Считаться с учётом скидки
5. **Логика доставки:** Порог бесплатной доставки (3000₽) считается от суммы товаров **ДО** скидки

**Пример из HowToDemo:**

```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":1000,"qty":2}],"promo":"WELCOME10"}'
```

Ожидаемый ответ:
```json
{
  "goods": 2000,
  "discount": 200,
  "delivery": 300,    // Порог 3000 не достигнут (2000 < 3000)
  "total": 2100        // 2000 - 200 + 300
}
```

### Нефункциональные требования

1. **Чистые функции:** Расчёт скидки должен быть в `src/pricing.mjs` чистой функцией
2. **Покрытие тестами:** Новая логика должна быть покрыта тестами в `tests/pricing.test.mjs`
3. **Без зависимостей:** Не вводить новые библиотеки

## Текущее поведение

**Код-доказательство текущей обработки запроса:** `src/server.mjs:29-42`

```javascript
if (req.url === '/quote' && req.method === 'POST') {
  let body;
  try {
    body = await readJson(req);
  } catch {
    return send(res, 400, { error: 'тело запроса не разобралось как JSON' });
  }
  try {
    return send(res, 200, quote(body?.items));  // ← Только items, без promo
  } catch (err) {
    return send(res, 400, { error: err.message });
  }
}
```

**Код-доказательство структуры ответа:** `src/pricing.mjs:48-52`

```javascript
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };  // ← Нет discount
}
```

## Критерии готовности

1. `POST /quote` принимает поле `promo` и обрабатывает его
2. Известные коды дают процент скидки от товаров
3. Неизвестный код → HTTP 400 с текстом ошибки
4. Ответ содержит `discount` и обновлённый `total`
5. Порог бесплатной доставки считается от суммы товаров ДО скидки
6. Расчёт скидки — чистая функция в `src/pricing.mjs`
7. `node --test "tests/*.test.mjs"` проходит без ошибок

## Риски и неопределённости

### Технические риски

1. **Хранение промо-кодов:** В условии не указано, где хранить валидные коды
   - **Опции:** локальный объект в коде / БД / внешний сервис
   - **Риск:** Неправильный выбор усложнит будущие изменения

2. **Обратная совместимость:** Существующие клиенты могут не отправлять `promo`
   - **Митигация:** Поле `promo` необязательное, поведение без него сохраняется

### Неопределённости

1. **Какие промо-коды считать валидными?**
   - В условии указан только пример `WELCOME10`
   - Нужно определить минимальный набор для MVP

2. **Формат хранения скидок:**
   - Процент (как в примере WELCOME10) или фиксированная сумма?

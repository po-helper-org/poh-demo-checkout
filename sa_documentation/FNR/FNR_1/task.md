## Проблема

**Симптом:** Промо-коды обещаны продавцам, но механики расчёта заказа с учётом скидки не существует. Текущий эндпоинт `POST /quote` принимает только позиции заказа и возвращает `{goods, delivery, total}` без учёта возможных скидок.

**Воздействие:** Скидки считаются вручную в переписке, что приводит к расхождениям между суммой, озвученной покупателю в чате, и фактической суммой к оплате.

**Код-доказательство симтома:**

```javascript
// src/pricing.mjs:617-621
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

Функция `quote` принимает только `items` и возвращает только `{goods, delivery, total}` без поля `discount`.

```javascript
// src/server.mjs:653-666
if (req.url === '/quote' && req.method === 'POST') {
  // ...
  return send(res, 200, quote(body?.items));
}
```

Эндпоинт передаёт в `quote()` только `body?.items`, поле `promo` не обрабатывается.

## Контекст

**Ограничения текущей реализации:**

1. **Отсутствие механизма скидок:** В `src/pricing.mjs` нет функций для расчёта скидок по промо-кодам.
2. **Отсутствие хранения промо-кодов:** Нет конфигурации или хранилища известных кодов и их правил скидок.
3. **Структура ответа:** Текущий ответ `{goods, delivery, total}` не содержит поля `discount`.

**Требования к бизнес-логике:**

1. Скидка применяется только к стоимости товаров (`goods`), не к доставке.
2. Порог бесплатной доставки считается от суммы товаров ДО применения скидки.
3. Неизвестный промо-код должен возвращать ошибку 400 с внятным сообщением, а не молчаливый ноль скидки.

**Код-доказательство требований:**

```javascript
// src/pricing.mjs:609-611
export function deliveryFee(amount) {
  return amount >= FREE_DELIVERY_FROM ? 0 : DELIVERY_FEE;
}
```

Функция `deliveryFee` уже проверяет порог `FREE_DELIVERY_FROM` (3000) и возвращает 0 при достижении. Это подтверждает, что порог бесплатной доставки существует и должен сохраниться.

## Диагноз

**Тип задачи:** Расширение функционала (новая фича).

**Что сломано:** Ничего — функционал отсутствовал с начала.

**Корень проблемы:** Архитектурное упущение — первоначальная реализация `POST /quote` не предусматривала маркетинговые инструменты скидок.

**Требуемые изменения:**

1. **`src/pricing.mjs`:**
   - Добавить конфигурацию известных промо-кодов и процент скидки (например, `WELCOME10: 10%`).
   - Добавить чистую функцию `applyPromo(goodsAmount, promoCode)` для расчёта скидки.
   - Модифицировать функцию `quote(items, promoCode?)` для acept опционального `promoCode` и возврата `{goods, delivery, discount, total}`.
   - Обеспечить, чтобы `deliveryFee()` считался от `goods` (до скидки), а `total` = `goods + delivery - discount`.

2. **`src/server.mjs`:**
   - Разобрать дополнительное поле `promo` из тела запроса (`body?.promo`).
   - Передать `promo` в функцию `quote()`.
   - Вернуть 400 с ошибкой, если `promo` передан и неизвестен.

3. **`tests/pricing.test.mjs`:**
   - Добавить тесты для функции `applyPromo()`.
   - Добавить тесты для `quote()` с promo-кодом.
   - Добавить тесты для валидации неизвестного promo-кода.
   - Убедиться, что порог бесплатной доставки считается от `goods` до скидки.

## HowToDemo (критерий готовности)

```bash
npm start
curl -sX POST localhost:8080/quote -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":1000,"qty":2}],"promo":"WELCOME10"}'
```

Ожидаемый ответ:
```json
{
  "goods": 2000,
  "discount": 200,
  "delivery": 300,
  "total": 2100
}
```

Без `promo` ответ остаётся прежним. Неизвестный код — `400` с внятным текстом.

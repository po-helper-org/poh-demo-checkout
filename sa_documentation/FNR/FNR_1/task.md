# FNR-1: Плата за упаковку по числу посылок в /quote

## Статус
Новая задача

## Категория
Функциональность

## Описание проблемы

### Симптом
Эндпоинт `POST /quote` рассчитывает доставку одной фиксированной ставкой на весь заказ (300 ₽, бесплатно от 3000 ₽). Для крупных заказов, требующих разбиения на несколько посылок, расходы на упаковку каждой посылки не учитываются, что приводит к финансовым потерям.

### Текущее поведение
**Файл:** `src/pricing.mjs:48-52`

```javascript
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

Функция `quote()` возвращает три поля:
- `goods` — сумма товаров
- `delivery` — фиксированная 300 ₽ или 0 при `goods >= 3000`
- `total` — сумма товаров и доставки

Отсутствует учёт количества посылок и стоимости упаковки.

### Ожидаемое поведение

#### Расчёт количества посылок
- 1 посылка вмещает до 5 единиц товара
- Единицы = сумма `qty` по всем позициям заказа
- Посылок = `ceil(единицы / 5)`

#### Стоимость упаковки
- 50 ₽ за каждую посылку
- Всегда взимается (даже при бесплатной базовой доставке)
- Прибавляется к полю `delivery`

#### Структура ответа
```javascript
{
  goods: <сумма товаров>,
  packages: <число посылок>,
  delivery: <базовая доставка (300 или 0) + упаковка (50 * packages)>,
  total: <goods + delivery>
}
```

## Контекст

### Ограничения
1. **Без внешних зависимостей** — сервис не имеет зависимостей, новые не вводятся
2. **Обратная совместимость** — поле `goods` не меняется, `total` по формуле
3. **Валидация** — заказ без позиций должен оставаться ошибкой
4. **Бесплатная доставка** — отменяет только 300 ₽, упаковка платится всегда

### Архитектурные решения

**Файл:** `src/pricing.mjs:1-4`

> Арифметика — в `src/pricing.mjs`, чистыми функциями. `src/server.mjs` только разбирает запрос и отдаёт коды.

Требуемые изменения должны быть реализованы как чистые функции в `src/pricing.mjs`.

### Задействованные компоненты

| Компонент | Файл | Роль |
|-----------|------|------|
| HTTP-обёртка | `src/server.mjs:26-46` | Парсит JSON, вызывает `quote()`, коды ответов |
| Расчёт котировок | `src/pricing.mjs:48-52` | Основная логика, требует расширения |
| Тесты | `tests/pricing.test.mjs` | Покрытие новой логики тестами |

## Примеры

### Пример 1: Несколько посылок с платной доставкой

**Запрос:**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":100,"qty":6}]}'
```

**Расчёт:**
- Единиц: 6 (qty=6)
- Посылок: `ceil(6 / 5) = 2`
- Товары: 100 × 6 = 600 ₽
- Доставка: 300 ₽ (базовая) + 100 ₽ (2 × 50) = 400 ₽
- Итого: 600 + 400 = 1000 ₽

**Ожидаемый ответ:**
```json
{"goods":600,"packages":2,"delivery":400,"total":1000}
```

### Пример 2: Бесплатная доставка, упаковка платится

**Запрос:**
```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":5000,"qty":1}]}'
```

**Расчёт:**
- Единиц: 1
- Посылок: `ceil(1 / 5) = 1`
- Товары: 5000 ₽
- Доставка: 0 ₽ (базовая бесплатна) + 50 ₽ (1 × 50) = 50 ₽
- Итого: 5000 + 50 = 5050 ₽

**Ожидаемый ответ:**
```json
{"goods":5000,"packages":1,"delivery":50,"total":5050}
```

### Граничные случаи

| Ситуация | Единиц | Посылок | Ожидание |
|----------|--------|---------|----------|
| 5 единиц | 5 | 1 | Максимальная загрузка посылки |
| 6 единиц | 6 | 2 | Первая единица второй посылки |
| 0 позиций | 0 | — | Ошибка валидации (текущее поведение) |
| Единицы = 0 (qty=0) | 0 | — | Ошибка валидации (текущее поведение: `qty <= 0`) |

## Как проверить

### Тестовые сценарии
1. Базовый случай с платной доставкой и несколькими посылками
2. Бесплатная доставка с платной упаковкой
3. Ровно 5 единиц (одна полная посылка)
4. 6 единиц (переход на вторую посылку)
5. Граничные случаи валидации

# Задача FNR-1: Округление итогов в ответе /quote до целых рублей

## Метаданные

- **Источник**: Issue #10
- **Тип**: Рефакторинг API-контракта
- **Приоритет**: P2
- **Компонент**: Сервис расчёта стоимости заказа
- **Затронутые файлы**: `src/pricing.mjs`, `src/server.mjs`, `tests/pricing.test.mjs`

---

## 1. Диагноз проблемы

### 1.1 Симптом

Эндпоинт `POST /quote` возвращает дробные значения в полях `goods`, `delivery`, `total`. Платёжная форма на фронтенде отображает только целые рубли, что создаёт визуальное расхождение между данными API и UI.

**Доказательство из кода:**

`src/pricing.mjs:48-52` — функция `quote()` возвращает точные значения без округления:

```javascript
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

`src/server.mjs:39` — HTTP-обработчик напрямую передаёт результат `quote()` в ответ:

```javascript
return send(res, 200, quote(body?.items));
```

### 1.2 Воспроизведение

Тестовый случай из HowToDemo:

```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":333,"qty":3}]}'
```

Текущее поведение:
```json
{"goods":999,"delivery":300,"total":1299}
```

При этом пример с целыми числами маскирует проблему. Дробное проявляется при ценах с копейками:

```bash
curl -sX POST localhost:8080/quote \
  -H 'content-type: application/json' \
  -d '{"items":[{"sku":"a","price":333.33,"qty":3}]}'
```

Ожидаемый текущий ответ (до фиксации):
```json
{"goods":999.99,"delivery":300,"total":1299.99}
```

### 1.3 Корень проблемы

**Отсутствует этап округления** в цепочке расчёта→сериализации ответа.

Точки внедрения округления:
1. **В `quote()`** (`src/pricing.mjs:48-52`) — округлять перед возвратом
2. **В HTTP-обработчике** (`src/server.mjs:39`) — округлять после вызова `quote()`
3. **В сериализации** (`src/server.mjs:10-16`) — форматировать при `JSON.stringify`

## 2. Контекст и ограничения

### 2.1 Архитектурные ограничения

Из `CLAUDE.md`:

> Арифметика — в `src/pricing.mjs`, чистыми функциями. `src/server.mjs` только разбирает запрос и отдаёт коды: логика в обёртке — логика, которую тест не увидит.

> Зависимостей у сервиса нет. Новая заводится, только если задачу нечем закрыть из стандартной библиотеки, и причина пишется рядом с кодом.

### 2.2 Область применения

Округлению подлежат **все** числовые поля в ответе `/quote`:
- `goods` — сумма товаров
- `delivery` — стоимость доставки
- `total` — итоговая сумма

### 2.3 Правило округления

Из описания задачи: "до целых рублей по правилам арифметики".

В JavaScript: `Math.round()` — стандартное арифметическое округление.
- `.5` округляется вверх
- `< .5` округляется вниз

## 3. Анализ вариантов решения

### 3.1 Вариант 1: Округление в `quote()` (domain-слой)

**Место:** `src/pricing.mjs:48-52`

**Плюсы:**
- Логика округления централизована в domain-слое
- Тесты покрывают округление автоматически
- Все callers получают округлённые значения

**Минусы:**
- Теряется точность для потенциальных внутренних расчётов
- Нарушается принцип "чистые функции" — функция начинает нормализовать выход

### 3.2 Вариант 2: Округление в HTTP-обработчике (boundary)

**Место:** `src/server.mjs:39`

**Плюсы:**
- Domain-слой остаётся точным
- Округление применяется только на границе API
- Изменения локализованы в одном месте

**Минусы:**
- Тесты `pricing.test.mjs` не покрывают округление (они тестируют `quote()` напрямую)
- Требуется отдельная проверка в HTTP-тестах

### 3.3 Вариант 3: Форматирование при сериализации

**Место:** Функция `send()` в `src/server.mjs:10-16`

**Плюсы:**
- Максимальная локализация
- Оригинальные объекты не модифицируются

**Минусы:**
- Сложно применить избирательно (только для `/quote`)
- Сериализатор должен "знать" о структуре ответа
- Наименее явное решение

## 4. Пограничные случаи

### 4.1 Точные вычисления vs округление вывода

При суммировании округлённых значений может возникнуть расхождение:

```
goods: 1000.50 → 1001
delivery: 299.50 → 300
total: 1300.00 → 1300
```

Но `1001 + 300 = 1301 ≠ 1300`

**Вопрос:** Округлять `total` independently или как `Math.round(goods + delivery)`?

### 4.2 Нулевые значения

```
goods: 0
delivery: 0
total: 0
```

Округление нуля даёт ноль — проблем нет.

### 4.3 Крупные суммы

```
goods: 99999.99 → 100000
```

Потеря точности ~0.001% — приемлемо для отображения.

### 4.4 Отрицательные значения

По коду (`src/pricing.mjs:26-27`) отрицательные цены запрещены:

```javascript
if (!Number.isFinite(item.price) || item.price < 0) {
  throw new Error(`некорректная цена в позиции ${item.sku}`);
}
```

Отрицательные значения невозможны.

```javascript
test('итог складывает товары и доставку', () => {
```

# Task: Эндпоинт GET /healthz с временем работы процесса

## FNR ID
FNR-1

## Статус
Новое

## Тип задачи
Рефакторинг / Корректировка существующей функциональности

## Проблема

Эндпоинт `GET /healthz` существует в кодовой базе (`src/server.mjs:28`), но его текущая реализация не соответствует требованиям:

**Текущее поведение:**
```javascript
if (req.url === '/healthz') return send(res, 200, { ok: true });
```
[`src/server.mjs:28`](../../src/server.mjs:28)

Возвращает `{ ok: true }` вместо требуемого формата `{ status: "ok", uptime_sec: <целое> }`.

**Проблема:** Отсутствует поле `uptime_sec` — целое число секунд с момента старта процесса.

## Контекст

**Проект:** `poh-demo-checkout` — простой HTTP-сервис расчёта стоимости заказа на Node.js.

**Архитектурные границы (из CLAUDE.md):**
- Арифметика вынесена в `src/pricing.mjs`, чистые функции
- `src/server.mjs` только разбирает запрос и отдаёт коды — логика в обёртке
- Зависимостей у сервиса нет, новая заводится только если задачу нечем закрыть из стандартной библиотеки

**Существующая тестовая инфраструктура:**
- Тесты в `tests/pricing.test.mjs` используют `node:test` + `node:assert/strict` [`tests/pricing.test.mjs:1-2`](../../tests/pricing.test.mjs:1-2)
- Покрывают только чистые функции из `pricing.mjs`, не HTTP-слой
- Для тестирования HTTP-эндпоинта потребуется запуск реального сервера

**Точка входа приложения:**
- `src/server.mjs::app` — функция-обёртка для HTTP-обработчиков [`src/server.mjs:27`](../../src/server.mjs:27)
- `send(res, code, body)` — утилита для JSON-ответов с правильными заголовками [`src/server.mjs:11-18`](../../src/server.mjs:11-18)

## Root Cause

Эндпоинт `/healthz` был добавлен при создании файла 2026-08-17 коммитом `ca11525c` "feat: демо-стенд контура производства" с минимальной реализацией `{ ok: true }`, которая не содержала `uptime_sec`.

## Диагноз

**Что сломано:**
1. Формат ответа `/healthz` не соответствует спецификации: поле `ok` вместо `status`
2. Отсутствует поле `uptime_sec` с целым числом секунд работы процесса

**Что требуется:**
1. Изменить тело ответа с `{ ok: true }` на `{ status: "ok", uptime_sec: Math.floor(process.uptime()) }`
2. Добавить тест в `tests/`, проверяющий:
   - Код ответа 200
   - Заголовок `Content-Type: application/json`
   - Поле `status` со значением `"ok"`
   - Поле `uptime_sec` — целое число, `>= 0`

## Критерии приёмки

1. `GET /healthz` возвращает код **200** и заголовок **`Content-Type: application/json`**
2. Тело ответа содержит поле **`status`** со значением **`"ok"`** (строка)
3. Тело ответа содержит поле **`uptime_sec`** — **целое число** (округлено вниз через `Math.floor(process.uptime())`)
4. Значение `uptime_sec` **>= 0**
5. Маршрут не требует ни параметров, ни заголовков
6. Есть тест в `tests/`, проверяющий все вышеперечисленные условия

## Нефункциональные требования

| Требование | Значение | Способ проверки |
|------------|----------|-----------------|
| Время ответа | < 10ms | Нет вызовов БД/внешних API |
| Зависимости | Стандартная библиотека Node.js | `process.uptime()` — встроенный API |

## 1. Деконструкция запроса

### 1.1. Проблема

**Что сломано/чего не хватает:**

Текущий поток оформления заказа требует обязательной регистрации пользователя на шаге оплаты. Это вызывает отток клиентов — покупатели уходят, не завершая оформление, когда сталкиваются с необходимостью создать учётную запись.

**Источники:**
- Описание Issue #43: «Сейчас оформить заказ можно только после регистрации: на шаге оплаты форма требует логин, и часть покупателей уходит именно здесь.»
- БФТ (быстрый проход): Impact 4/5 — «Снижает отток клиентов на этапе оплаты за счёт удаления обязательной регистрации»

### 1.2. Контекст

**Окружение:**
- Демо-репозиторий `poh-demo-checkout` — сервис расчёта стоимости заказа
- Текущий функционал: `POST /quote` — расчёт суммы позиций, доставки, итога
- Стек: Node.js 22, стандартная библиотека (без внешних зависимостей)

**Ограничения:**
- Существующий флоу с регистрацией должен остаться без изменений
- Почта обязательна — используется для поиска заказа в поддержке
- Повторный заказ на ту же почту не должен создавать дубль профиля
- Зависимости не добавляются без необходимости (CLAUDE.md:67)

**См. также:**
- Issue #41 — эталонный прогон того же текста через `claude -p`
- БФТ: "Текст намеренно дословно повторяет #41: тот прогон сделан агентом claude -p и служит эталоном"

### 1.3. Ожидание

**Что пользователь хочет получить:**

1. Возможность оформить заказ без создания учётной записи
2. Форму гостевого оформления с полями: email (обязательно), адрес доставки, телефон, ФИО (опционально)
3. Письмо со статусом заказа на указанный email
4. Ссылку для создания аккаунта (или входа, если аккаунт уже есть) с привязкой过往 заказов
5. Обработку повторных заказов на один email без создания дублей профилей

**How to demo (из БФТ):**
1. Открыть корзину → выбрать «Оформить без регистрации»
2. Ввести email, адрес, телефон, ФИО
3. Завершить оформление → проверить почту (письмо со статусом)
4. Перейти по ссылке → создать/войти в аккаунт → заказ в профиле
5. Повторить с тем же email → нет подсказки о занятости → ссылка на вход
6. После входа → новый заказ привязался к профилю

## 2. Исследование кодовой базы

### 2.1. Текущая реализация

**Анализ по repomix-output.xml:**

**Существующие компоненты:**

| Компонент | Файл | Ответственность |
|-----------|-------|------------------|
| Расчёт стоимости | `src/pricing.mjs` | Арифметика заказа: сумма позиций, доставка, итог (функции `subtotal`, `deliveryFee`, `quote`) |
| HTTP-обёртка | `src/server.mjs` | Endpoints: `/healthz`, `POST /quote` — разбор JSON, коды ответов |
| Тесты | `tests/pricing.test.mjs` | Проверка расчёта (8 тестов) |

**Доказательства кода:**

```javascript
// src/server.mjs:714-728
if (req.url === '/quote' && req.method === 'POST') {
  let body;
  try {
    body = await readJson(req);
  } catch {
    return send(res, 400, { error: 'тело запроса не разобралось как JSON' });
  }
  try {
    return send(res, 200, quote(body?.items));
  } catch (err) {
    return send(res, 400, { error: err.message });
  }
}
```

Текущий эндпоинт `/quote` принимает только массив позиций (`items`) и возвращает расчёт стоимости. Нет:
- Аутентификации/авторизации
- Сохранения заказов
- Отправки email
- Управления пользователями

### 2.2. Отсутствующие компоненты

Для реализации гостевого заказа требуются:

| Компонент | Статус | Доказательство |
|-----------|--------|----------------|
| Модель заказа | Отсутствует | В репомix нет файлов с `order`, `checkout` в имени |
| Модель пользователя | Отсутствует | Нет User Service, auth-логики |
| Email-сервис | Отсутствует | Нет отправки писем (только Node.js stdlib) |
| Сессии/токены | Отсутствуют | Нет stateful session management |
| База данных | Отсутствует | Сервис stateless, хранения нет |

**Вывод:** Текущий кодовой базис не содержит инфраструктуры для:
1. Сохранения заказов
2. Управления пользователями/профилями
3. Отправки email-уведомлений
4. Связывания гостевых заказов с профилями при регистрации

### 2.3. Корень проблемы

**Диагноз:** Проблема не баг, а **отсутствие функциональности**. Текущий сервис (`poh-demo-checkout`) реализует только расчёт стоимости заказа и не предназначен для полного flow оформления заказа с пользователями.

**Аргументация:**
1. Назначение репозитория — демо-стенд контура производства (README.md:3-6)
2. Код намеренно простой — «чтобы предметом разбора был контур, а не предметная область» (README.md:5-6)
3. Зависимостей нет — это свойство сервиса (CLAUDE.md:66-67)

**Следовательно:** Реализация полноценного гостевого чекаута выходит за границы текущего scope демо-репозитория и потребует:
- Либо существенного расширения функционала (новые сервисы, база данных, email)
- Либо изменения назначения репозитория

## 3. Открытые вопросы (из БФТ)

1. **Данные гостевого заказа:** Что происходит с адресом/телефоном при регистрации по ссылке из письма — подставляются ли в профиль автоматически?

2. **Самостоятельная регистрация:** Если пользователь не перешёл по ссылке из письма, а зарегистрировался самостоятельно с тем же email — привяжется ли заказ автоматически?

3. **Lifetime сессии:** Каков lifetime сессии гостя и статус заказа, если он бросил оформление на шаге ввода данных?

4. **Совместимость с текущим репо:** Каким образом гостевой чекаут вписывается в scope демо-сервиса расчёта стоимости?

# FNR-1: Минимальная сумма заказа для оформления

## Дата создания
2026-08-20

## Краткое описание
Система расчёта стоимости заказа не блокирует оформление заказов с суммой товаров ниже установленного порога, что приводит к приёму убыточных мелких заказов.

---

## 1. Симптом

**Что наблюдается:**
- Endpoint `/quote` принимает и успешно обрабатывает заказы с любой суммой товаров, включая нулевую (если бы не существовала проверка на пустой массив позиций).
- Стоимость заказа рассчитывается корректно, но нет валидации минимального порога суммы товаров.

**Доказательство:**
`src/pricing.mjs:48-52` — функция `quote()` считает сумму товаров и доставку, но не проверяет минимальный порог:

```javascript
export function quote(items) {
  const goods = subtotal(items);
  const delivery = deliveryFee(goods);
  return { goods, delivery, total: goods + delivery };
}
```

`src/server.mjs:26-46` — обработчик `/quote` возвращает успешный ответ для любой суммы, прошедшей валидацию в `quote()`.

---

## 2. Ожидание

**Что должно быть:**
- При сумме товаров ниже установленного порога оформление должно отклоняться с понятным сообщением.
- Сообщение должно указывать, сколько именно не хватает до минимальной суммы.
- Стоимость доставки в проверку порога не входит — проверяется только сумма товаров (`goods`).
- Порог задаётся в одном месте, а не размазан по коду.

---

## 3. Корень проблемы

**Проблема:** В кодовой базе отсутствует:
1. Константа, определяющая минимальную сумму заказа.
2. Проверка минимальной суммы в функции `quote()`.
3. Сообщение об ошибке с указанием недостающей суммы.

**Почему:** Проект `poh-demo-checkout` является демо-стендом и не содержит этой бизнес-логики изначально.

**Точка внедрения:**
Проверка должна быть добавлена в `src/pricing.mjs` внутри функции `quote()`:
- После вычисления `goods = subtotal(items)` — сумма товаров уже известна.
- До вычисления `delivery = deliveryFee(goods)` — доставка в проверку не входит.

**Доказательство правильного места:**
`src/pricing.mjs:48-52` — текущий поток `quote()`. Добавление проверки после строки 48 и до строки 49 соответствует требованию «только товары, без доставки».

---

## 4. Текущее состояние компонентов

### 4.1 Арифметика расчёта
**Файл:** `src/pricing.mjs`

**Существующие константы:**
- `DELIVERY_FEE = 300` — стоимость платной доставки
- `FREE_DELIVERY_FROM = 3000` — порог бесплатной доставки

**Паттерн ошибок:**
Ошибки валидации выбрасываются как `Error` с текстовым сообщением на русском:
- `src/pricing.mjs:23` — `'заказ без позиций'`
- `src/pricing.mjs:25` — `'некорректная цена в позиции ${sku}'`
- `src/pricing.mjs:28` — `'некорректное количество в позиции ${sku}'`

**Доказательство:** Код выше + `tests/pricing.test.mjs:11-13` — паттерн проверки ошибок через `assert.throws()`.

### 4.2 HTTP-обёртка
**Файл:** `src/server.mjs`

**Обработка ошибок:**
`src/server.mjs:42-45` — catch вокруг `quote()` превращает любое `Error` в HTTP 400 с `{ error: err.message }`.

**Доказательство:**
```javascript
try {
  return send(res, 200, quote(body?.items));
} catch (err) {
  return send(res, 400, { error: err.message });
}
```

Это означает, что новая проверка достаточно выбросить `Error` — она автоматически превратится в корректный HTTP-ответ.

### 4.3 Тесты
**Файл:** `tests/pricing.test.mjs`

**Паттерн тестов валидации:**
`tests/pricing.test.mjs:11-13` — проверка ошибки «заказ без позиций»:
```javascript
test('заказ без позиций — ошибка, а не ноль', () => {
  assert.throws(() => subtotal([]), /без позиций/);
});
```

**Что нужно добавить:**
Тест на проверку минимальной суммы, аналогичный существующим тестам валидации.

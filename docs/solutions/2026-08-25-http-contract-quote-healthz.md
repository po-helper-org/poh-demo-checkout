# HTTP-контракт /quote и /healthz: методы, query, content-type, размер тела

## Ситуация

Сервер рос без единого HTTP-контракта, и каждый следующий клиент натыкался на новое:

- #100: не было `GET /healthz` — контролировать живость процесса было нечем (появился с `uptime_sec`).
- #121: маршрут с query-строкой (`/healthz?x=1`) уходил в 404 — сравнение шло по полному `req.url`.
- #126: `POST /quote` принимал любой content-type и падал на не-JSON теле.
- #122: тело запроса читалось целиком без ограничения — один запрос исчерпывал память.
- #120: на `/healthz` отвечали любые методы, а не только GET.

## Причина

Роутер сравнивал сырую строку URL без нормализации, не валидировал метод и content-type, а
`readJson` не имел лимита. Каждый дефект жил, пока не упирался в реального клиента.

## Решение

- #104: `GET /healthz` → 200, `{status: "ok", uptime_sec}` из `process.uptime()`.
- #131: путь разбирается `new URL(req.url, "http://localhost")`, маршруты сравниваются по
  `pathname` для `/healthz`, `/stats`, `/quote`.
- #141: не-JSON content-type на `POST /quote` → 415.
- #144: лимит размера тела в `readJson` (64 KB) → 413 с телом `{"error": ...}`.
- #130: не-GET на `/healthz` → 405 `{error: "Method Not Allowed"}` с `Allow: GET`.

## Как проверить

Тесты `tests/server.test.mjs`: `GET /healthz?probe=1` → 200; `POST /quote` с `text/plain` → 415;
тело больше лимита → 413; `POST /healthz` → 405 с `Allow: GET`.

## Уроки

- Сравнение маршрута по сырому `req.url` ломается первым же query-параметром — всегда `URL` и
  `pathname`.
- Чтение тела без лимита — не «оптимизация», а DoS-рука: лимит ставят вместе с первым эндпоинтом.
- Контракт методов/кодов лучше зафиксировать тестами до того, как его начнут читать мониторинги и
  внешние клиенты.

# Веб-интерфейс расчёта: статика на голом Node и защита от path traversal

## Ситуация

У сервиса был только API. Для демо не хватало веб-страницы расчёта заказа: форма (SKU, цена,
количество), кнопка, результат, ошибка.

## Причина

Возможности не было: сервер не умел отдавать статические файлы, а frontend-файлов не существовало.

## Решение

- `static/index.html`, `static/app.js`, `static/style.css`: форма расчёта с валидацией полей,
  состояниями загрузки и ошибки, форматированием результата.
- Раздача статики прямо в `src/server.mjs` без внешних зависимостей: словарь MIME-типов,
  проверку пути и метода.
- Безопасность: проверка пути против выхода за корень статики (path traversal), статика — только на
  GET.
- Тесты на метод-валидацию `/stats` (405 на POST/PUT/DELETE с `Allow: GET`).

## Как проверить

Открыть корень сервиса в браузере, отправить расчёт; тесты `tests/server.test.mjs` на 405 `/stats`.

## Уроки

Ручная раздача статики обязана включать нормализацию пути — `../` в URL это первая атака на такие
серверы.

# main покраснел сам: тесты зависели от календаря, а промокод истёк

## Ситуация

`main` стал красным со 2 сентября, и ни один коммит в этом не был виноват: три теста в
`tests/pricing.test.mjs` считали скидку по текущей дате, а у `PROMO_CODES['SUMMER20']` срок действия
истёк 1 сентября (`src/pricing.mjs:23`). Последний зелёный прогон на `main` был 28 августа — CI
гоняется на коммиты, а календарь идёт сам.

Чем это стоило: три автономных прогона разработки подряд (#166, #167, #169) списаны в отказ вместе
с работой агента, который ничего не ломал — падали ровно эти три теста.

## Причина

Тесты не фиксировали момент времени: `quote` и `discountAmount` считали «сейчас» неявно. Истечение
срока промокода проверялось нечаянно — самим течением времени.

## Решение

`quote` и `discountAmount` получили необязательный параметр `now` (у `validatePromoCode` он уже
был), тесты фиксируют момент внутри срока акции. Поведение сервиса не изменилось — по умолчанию
`new Date()`. Дата промокода не двигалась намеренно: это предметные данные, и решение «продлить
акцию» принимает не тест. Добавлен явный тест на просроченность.

## Как проверить

Прогон полного набора тестов: 73 passed / 0 failed, в том числе явный тест истечения срока промокода.

## Уроки

- Любая работа с «сейчас» в коде должна принимать момент параметром — иначе тесты становятся
  миной замедленного действия с датой срабатывания из предметных данных.
- CI на коммиты не ловит дрейф календаря: у сроков действия в тестовых данных либо нет даты
  окончания, либо она зафиксирована вместе с фиксированным `now`.
